# 同步超时与失败状态设计

## 数据流与职责

```text
CCS 同一只读事务（5 秒、白名单、行数/字节上限）
  → 按行写入本轮临时用量投影
  → 关闭所有源游标及连接，释放源读锁
  → 本地流式回放（独立 120 秒预算、取消、512 行暂存）
  → 元数据补充与既有原子发布
  → 清理临时投影，返回真实终态
```

`sources.scan_sqlite` 继续作为来源协议唯一实现，保留现有签名、过滤、跨表一致性、原始投影指纹和结构校验。`sync.sync_sqlite` 负责两阶段编排，临时数据及规范化仍经过既有 `_Stager`，不新增迁移、不引入第二套金额或身份规则。

## D1：快照与本地处理解耦

- 使用 `store.data_dir / temporary` 下本轮独占的临时文件，仅记录 scan 返回的表标识和允许字段；优先采用打开即由上下文管理关闭/删除的 `TemporaryFile`，避免额外持久缓存协议。禁止完整库复制、pickle、原始 SQL 执行或读取配置表。
- 逐行写入、逐行回放，不累计全部明细到 Python 列表。投影有效载荷继续受 512 MiB 上限约束，记录封装开销由表数和每表最大行数共同限制；只写一份临时投影。
- 源读取仍为 5 秒，只有轻量投影和临时写入包含在源事务内。规范化、身份/内容指纹计算、应用库事务和 fsync 均在源连接关闭后进行。
- 本地回放/最终暂存采用独立 120 秒墙钟预算，保留每行/每批取消检查及 250 ms writer 等待上界；不要通过全局增加源限时修复。
- 本地预算超时使用独立安全错误（建议 `sync_processing_timeout`），不能继续报告源库忙；临时空间不足和写入失败按本地同步失败处理，不泄露路径。
- 同时响应显式 cancel 和 Store 退出取消；不能因只向 scan 传其中一个 Event 而遗漏另一个。元数据和发布继续使用既有取消/事务机制。
- 源扫描返回前不得调用 `_Stager.add/flush`。本地最后一批必须在本地预算内提交，之后才进入元数据/发布；不要在 read 返回后无预算地补交最后一批。
- 沿用 `source_projection_and_staging_ms` 总计，可增加源扫描及本地暂存分段耗时，便于区分后续故障；不记录个人资料或原始异常。

## D2：一致性、失败与资源释放

- 来源的 kind/name/location、实际结构版本、允许投影指纹及规范化事实身份保持原含义；临时文件名不成为 source_id。
- 只有完整扫描、完整暂存及后续原子发布成功才推进成功时间；异常通过 `_failed` 处理本轮staging，旧事实、占用、核对状态及原包保留。真实外部写锁无法取得时不能声称已持久清理：先在Store独立小锁保护的内存记录安全失败，再以有界事务尝试清理；提交后才移除记录。
- 同一Store下次开始同步前，通过独立原子恢复事务精确清理已知失败run和过期租约的stage/pricing并标failed，然后再进行active检查/创建新run。恢复不能因后续active拒绝而回滚，不清其他未过期有效run。跨进程重启无内存失败依据时仍遵循现有120秒租约，未过期可能暂时拒绝同步；不增加持久日志文件、schema或后台服务。
- 临时资源覆盖成功、源读取失败、本地回放失败、取消、超时和异常传播路径；Windows 上先关闭句柄再结束清理。硬杀残留不得触发批量清扫其他资料。
- 慢本地处理期间独立 CCS writer 可以提交；后续源修改不会改变本轮已完成快照。WAL/DELETE 的原有一致性回归必须保留。
- 不改变 SQL 备份/历史导入的输入协议；共享 `_Stager` 调整须检查这两条路径，避免套上不相关来源限制。

## D3：来源状态卡

- 显示优先级：正在同步 → 本次失败 → 需要核对 → 有历史成功 → 尚无成功资料。
- 当前 HTTP job 使用 `status`，持久 `ledger.last_attempt` 使用 `state`；集中规范化后判断。刷新优先采用本次启动的最新 job，缺少 job 时从最近持久尝试恢复状态。`ledger.last_sync` 是最近成功，不能用它代替最近尝试。
- 有历史的失败显示“同步失败”，错误原因持续可见，并说明“当前显示已保存的本地数据”；无成功时说明“尚未成功同步，当前统计不代表实际用量”，已存在待核对事实时同时保留已保存资料说明。保留独立上次成功时间/覆盖范围，不把待核对后新增事实冒称上次成功快照，不修改统计数值和查询能力。
- 重试中隐藏旧失败说明、禁用重复同步；新任务成功或需要核对后更新标签并结束轮询。页面初始化在首次来源卡渲染前尽可能恢复当前任务，避免先呈现旧成功状态。
- 不新增模态确认、后台同步或阻断用户查历史资料的流程。
- 已知终态不能被后续页面刷新失败覆盖；同步流程代际保护须覆盖迟到成功、错误和finally。初始化失败不得丢失running任务的watcher或永久禁用按钮，旧初始化不能覆盖用户新任务/新分析。

## 兼容、取舍与回滚

- 保持应用 schema3、外部 23/24、内部投影23以及既有冻结材料协议，不手工升产品版本。
- 取舍：增加一次临时磁盘读写，换取源读锁更短和本地处理预算独立；磁盘失败必须明确且不发布半批次。
- 5 秒预算仍可能拒绝真正慢的源读取；本次不承诺任意规模/存储设备都在 5 秒内完成，也不放宽来源锁保护。
- 120 秒仅为本地回放/暂存保护，不冒充整轮同步 SLA；发布及核对复杂度保持既有行为。
- 本次基于隔离合成数据验收，不触发真实台账同步；用户正常启动成品后的同步沿用既有机制。保留经核实的桌面旧版用于回退。
- 本机打包运行时与最近验收记录比较；运行时/配方变化按发布合同追加全面专项，不以历史回执冒充本轮验收。

## 需求

### R1：规范能指导当前项目开发

补齐 backend 的目录、SQLite、错误处理、日志与质量规范；补齐 frontend 的目录、DOM 组件、状态、JavaScript 数据边界与质量规范。每个主题须给出真实源码或测试入口、可用例子及常见错误，移除占位文字与不适用的技术栈提示。

### R2：业务契约与分题规范一致

保留现有 backend/frontend 两份契约作为业务与跨层约束的主要入口，按当前实现核对签名、请求形状、状态与错误码。维护说明使用简体中文，技术标识原样保留。分题规范通过引用细化修改方法，避免重复维护业务规则。不能把代码中未验证的行为或建议改进写成已接受契约。

### R3：思考指南与导航适用于 aha

调整三个 guides 文档中的本项目示例、入口与跨层检查，明确 HTTP 参数校验和事务内业务重检的不同职责。移除 React hooks 专题模板，其适用内容归并到页面事件与状态规范；更新全部现行引用。README 提供开发规范入口。

### R4：未归档工作的记录真实且可追溯

保留 `00-bootstrap-guidelines` 的稳定目录和身份，补齐实际目标、交付范围、证据映射、验收清单和收尾条件。完成项必须对应具体规范和检查结果，不能仅批量勾选。可将任务标题、说明和备注改为准确的中文表述，保留初始化来源。不改写已归档任务或历史日志；初始化任务继续保持未归档状态，待用户验收后再决定归档。

### R5：验证结论与权限范围准确

记录本轮文档检查与源码基线结果，明确历史原生验收的来源和时间范围。发现产品缺陷或行为与期望不一致时，记录证据并单独说明，不在文档校准中修改产品行为。任务保持可审阅的差异。

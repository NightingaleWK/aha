# 清爽表单与便捷时间筛选：设计 V0.2（已批准）

本稿对应 [PRD](prd.md)，任务状态为 `in_progress`。历史日汇总采用用户已确认的方案 A；用户已在完整最终摘要之后明确批准进入实施，实际完成情况以执行和验证记录为准。

## 1. 设计范围与职责

一次打通“选择项目/时间 → 预览 → 四个视图 → 保存/修订 → 冻结材料”。具体改动仍遵循现有本机 HTML/CSS/JavaScript 与 Python/SQLite 结构，来源读取保持不变。

| 层 | 职责 |
| --- | --- |
| 共享表单组件 | select 外观、搜索、列表焦点、开合、禁用和程序回填同步；用量范围分段选择；样式与标签规范 |
| 时间范围组件 | 面板草稿、日历、分钟编辑、快捷范围、跟随开关、取消和确认 |
| 页面状态 | 保存已生效的筛选意图和服务端返回的具体区间；控制预览失效、游标、勾选、报销主体和陈旧响应 |
| HTTP / Store 时间解析 | 校验新旧请求，统一北京时间，固定一次请求的当前时刻，产生规范化范围 |
| queries | 成员过滤、日/月/边界统计、完整性与排除说明、四视图和游标 |
| batches / evidence | 冻结实际区间及成员，哈希、修订兼容、HTML/JSON/CSV 范围一致，旧包重下载 |

## 2. 清爽表单与共用组件

### 外观与应用位置

- 复用现有青绿、背景、边框、字号与间距变量；字段标签保留在控件上方。主要控件约 44–48px，圆角 10px；正文/输入 16px、按钮 15px、标签 14px、次要至少 13px。
- 首页以项目选择和一个时间范围入口为主体，“可用用量/全部用量”使用并排按钮。保持项目、用量、报销权限各自原含义。
- 项目管理、人工分配、报销币种、修订依据、状态选择和核对依据采用同类共享控件；业务按钮与状态流转约束不变化。

### 接入方式

增加本机共享组件脚本 `web/form-controls.js` 与时间选择脚本 `web/time-range-picker.js`，均在现有 app.js 之前加载；不建立另一套前端构建链。资源新增时核对 server.ASSETS、package-data 和 Windows 收集。

现有业务 select 的 value、option 与 disabled 继续作为业务值的所有者；增强层只提供呈现与交互，并经统一 change 路径通知现有页面逻辑。项目及特殊选项用原 ID，不以文字识别业务身份。

需要明确覆盖：

1. 动态增删选项后更新弹出列表。
2. 代码直接设置 value 后显式同步显示值，不能只依赖 MutationObserver；value 属性赋值并不保证 DOM attribute 变化。
3. 核对卡片动态创建的 select 通过同一挂载入口增强，销毁时清事件和浮层。
4. 增强后的按钮、搜索框、错误提示和标签具有完整可访问关系，原生控件不重复进入辅助技术的交互序列。
5. 禁用、忙碌、退出和权限变化同步到可见控件，不能点击外观正常但业务已经失效的副本。

共用浮层在普通页面与 dialog 内都可定位、收起和归还焦点；保持 Tab 自然顺序，支持方向键、Enter、Escape。外部点击判断须避免选项重绘移除事件 target 后误判，把本次内部点击当成外部点击。

## 3. 时间选择的交互与状态

### 面板结构

- 顶部：当天、近 24 小时、近 7/14/30 天、本月、全部。
- 主体：开始/结束日期与分钟输入、可选起止日的日历；按当前编辑端点高亮，长区间仍显示可核对的两端。
- 底部：“结束时间跟随当前时刻”、取消、确定。范围无效时在面板内报错并禁用确认。
- 首页入口显示范围名称和具体起止时间；完整性提示与历史汇总排除说明紧邻统计结果。

`draftRange` 只在面板内部编辑；打开从已生效条件复制，取消或 Escape 丢弃草稿，不清原分析。确定后一次应用新条件，调用既有失效流程，再发起分析；无需用户再点一次更新预览。

`appliedRangeIntent` 表示选择意图；`resolvedRange` 表示服务端本次实际采用的具体边界。再次更新预览时可重新解析跟随模式，保存/修订/导出则只使用 analysis 已绑定的 resolvedRange。

用户手动编辑项目或用量范围时仍遵守原预览失效规则；被较新条件替代的分析响应不能覆盖当前界面或恢复旧保存身份。

### 快捷状态与时间显示

对外语义以 PRD“时间范围口径”为准。选择当天、近 24 小时、近 N 天或本月时默认开启跟随；选择全部时关闭并禁用跟随。用户可主动切换为固定结束，固定锚点从最近一次服务端解析结果取得；首次尚无结果时使用 status 返回的服务端 now，不以浏览器所在时区或本机时钟猜测。

固定快捷范围的精确端点可在摘要中显示到秒。用户手动编辑任何端点后转为自定义分钟范围；端点精度与快捷身份不会暗中同时保留互相矛盾的状态。再次打开面板显示当前实际条件，不把原近 24 小时误显示为 24 小时加一分钟。

跟随开启并不让已生效的摘要在后台跳动；只有用户重新预览才改变具体边界。首次打开、快捷选择和确认均可更新本地查询，但不触发额外来源同步。

## 4. 统一时间合同与兼容

### 请求入口

主页面及目标批次的 `/analysis` 两个入口新增 `time_range` 对象，project/availability/classification/目标版本校验沿用原合同。新请求不再同时发送 start_date/end_date；同一请求混用新旧范围直接返回 invalid_time_range，避免两个范围所有者。旧日期请求保持原语义和 Store.analyze 调用兼容。

| time_range 形式 | 允许字段及解释 |
| --- | --- |
| 跟随快捷 | `kind="preset"`、`preset`、`follow_now=true`；不接受手动端点。 |
| 固定快捷 | `kind="preset"`、`preset`、`follow_now=false`、`end_before`；后者为带 `+08:00` 的秒级 ISO 排他结束时刻，由已有解析结果或明确锚点产生。 |
| 全部 | `kind="preset"`、`preset="all"`、`follow_now=false`；不接受端点，读取当前本地覆盖的完整自然日范围。空库返回安全的暂无日期提示，不构造虚假覆盖。 |
| 固定自定义 | `kind="custom"`、`start`、`end`、`follow_now=false`；端点严格为 `YYYY-MM-DDTHH:mm`，按北京时间解释，包含起止分钟。 |
| 跟随自定义 | `kind="custom"`、`start`、`follow_now=true`；不发送 end，采用本次服务端截止秒。 |

`preset` 枚举固定为 `today/last_24h/last_7d/last_14d/last_30d/month/all`。新对象拒绝未知字段、错误类型、错误精度/时区、缺端点、倒置或溢出范围；同一分钟的自定义起止允许，表示一分钟。

增加 `Store.analyze_time_range(...)` 门面和 queries 同名入口；与旧 analyze 共享内部的规范化分析实现，不复制一套 SQL/金额/占用逻辑。统一时间模块 `time_ranges.py` 供 HTTP、Store 和冻结兼容使用。`GET /api/status` 增加带北京时间偏移的秒级 now，供尚无分析时初始化面板；首次固定锚点由该当前秒加一得到 end_before，保持实际截止秒一致，不改变同步触发方式。

### 单次解析与身份

服务端每次新分析只取一次 clock，来源事件是整数秒；跟随结束采用 `floor(now_epoch)+1` 为排他边界，包含当前秒，不扩到未来分钟末。连续 24 小时的开始为该排他边界减 86400 秒。固定自定义开始落在开始分钟零秒，结束为手动结束分钟加 60 秒。自然日/月起点均按北京时间计算；固定快捷以 `end_before-1秒` 所在日期/月为锚点。

返回及冻结的 `time_range` 为版本 1 对象，包含：

- `version=1`、`timezone="Asia/Shanghai"`、标准化秒级 `start_at` 与 `end_before`。
- `precision=day|minute|second`、`intent`（原选择意图）和 `resolved_at`（解析时刻）。
- `rollup_policy="full_days_only"`，这是用户所选 A 的服务端规则，不能由请求改成别的规则。

内部类型由这两个时刻导出整数 `start_epoch/end_exclusive_epoch`，统一使用半开区间。日期包络 start_date/end_date 仍返回，供旧列表和旧记录兼容，不能再次用于精确查询过滤。页面摘要按精度显示实际含入的结束时刻，即 end_before 的前一秒；手动输入旁明确提示包含结束分钟。

查询的 analysis.selection_hash 和游标绑定规范化边界、时区/粒度策略及既有版本/项目/主体；不绑定每次都变化的 resolved_at，也不让不同快捷名称造成同一实际范围的假差异。冻结成员摘要与业务 hash 的区别见第 6 节。

## 5. 事实过滤与统计分段

### 已确认的不变量

- 明细 event_time 是实际事件秒，按规范化区间过滤。
- 历史日汇总的 event_time 只是日期零点投影，不能当作真实调用时刻（`ledger.py:33`）。
- 精确金额、大整数 Token、待核对、已占用、目标修订的自身豁免与跨粒度独占继续使用既有权威逻辑。

### 已确认的 A 方案

仅在某个历史日汇总的完整自然日落入范围时采用该汇总；部分覆盖的边界日汇总不计入，单独列出不能按时间分割的依据及原因。用户可明确选择改查整天，组件不能悄悄扩大原区间。

统计将范围分为互斥部分：完整月读现有月统计，剩余完整日读日统计，至多两个部分日通过已索引的实际明细聚合。单日内范围只产生一个边界段。不得重复合计、扫全历史到 Python，或用日/月总数冒充部分日。

摘要、每日、模型、排除说明与原始成员都由同一个范围合同驱动；未归属计数也一样处理。时间粒度不能确定造成的不完整，需与已有的待核对/已占用原因区分；不要把它自动创建为需要人工合并消费身份的核对事项。

新增 `time_coverage={complete, omitted_rollup_count, omitted_days, reason}`，reason 在有遗漏时为 `daily_rollup_has_no_event_time`，否则为 null；omitted_days 仅需列首尾不完整日，数量有界。遗漏探测使用同一项目与有效覆盖依据，不把已压制的重复候选重新当成确定成员。

新分析的 summary_complete 为“没有范围内待核对项，且 time_coverage.complete 为 true”。时间粒度遗漏不增加 pending_count，不自动新建核对事项；它与已确定的占用排除分别表达。仅有被排除历史汇总时，界面不能显示成已证明零消费，且仍因没有可用成员而不能保存。

不能把全天汇总的完整费用冒称为所选小时内的排除金额，也不能用它从范围内匹配/可用金额中相减。存在其他合法、确定的可用成员时允许保存这些成员，在页面和材料中保留不完整说明及被略过的日期。用户选择“改查整天”须明确触发新分析，不隐式扩大当前范围。

## 6. 冻结、修订与材料

兼容依据见 [源码核查](research/compatibility-findings.md)。应用库版本保持 schema3，不改事实与报销表结构，使用既有 analysis_json 存储新增范围与完整性元数据；是否补充可回退索引，以真实边界查询计划和工作量为依据。

### 新分析与冻结身份

冻结白名单新增 time_range、time_coverage、summary_complete、pending_count，连同原 warnings 保存；结果投影与报销详情展示实际范围。冻结验证及 frozen_basis 比较均使用规范化范围身份，不比较每次解析时刻。

- **查询身份**：queries 的 analysis.selection_hash 绑定范围、版本和项目/主体，供预览与游标使用。
- **成员身份**：batches 的冻结 selection_hash 保留现有按成员内容流式摘要的算法；时间范围不能改变同一批旧成员的摘要，frozen 修订仍据此核对原成员。
- **业务身份**：business_hash 在现有成员摘要/claim/项目等基础上加入规范化时间身份，防止同成员但不同范围的材料语义混淆；不把 resolved_at、快捷显示名称或跟随开关当成新的成员消费。

current 修订仍通过目标批次专用入口分析，不能借用自身占用豁免创建新报销；generation/base_version 和事务内权威重检保持。保存时不重新解析意图，也不重新取得 now。

### 旧冻结记录

旧 analysis_json 缺 time_range 时，仅在内存中按原 start_date/end_date 补出整天范围，标记来自旧日期。仅改用途继续读取原 revision_members，不重新查询当前来源或改分配，也不回写旧行。

旧冻结白名单未保存完整性布尔值（batches.py:552），因此缺少的 summary_complete/time_coverage 保留为未知，不解析文案来猜测、不用当前资料补判。新材料对这类旧 frozen 修订说明“沿用旧记录的冻结用量与说明，未重新判断历史资料完整性”。已保存新格式标志的记录则原样沿用。

### 材料版本与字节兼容

本任务实施后新生成的包使用 `manifest_version=4`，四文件名称和流式成员输出保持。导出信息.json 的 selection 增加规范化 time_range，另保存 time_coverage 和 summary_complete（旧 frozen 缺失时允许 null），HTML 显示对应的具体起止、时间解释和不完整原因；CSV 每日数据来自相同冻结成员。

版本 3 的 ZIP 仍按既有 zip_path/zip_hash/file_name 直接校验并下载，绝不重新生成。该路径不解析 manifest，已确认不依赖新 writer 的版本常量。旧版代码对新增材料的回写或新功能读取不在回退承诺内，但所有旧包及原始事实保持原样。

下载名沿用安全的日期包络、批次编号与修订号；精确时间放材料内部，文件名不增加冒号或扩大深路径压力。不同精确范围以实际内容及批次/修订身份区分。

## 7. 风险、验证与回退

- 风险：显示值与请求值脱节、取消清掉原分析、跟随模式在保存时漂移、首尾日统计重复、日汇总被当成零点事件、旧冻结版本解释改变。
- 验证：见 [实施计划](implement.md) 的跨层矩阵；原交互稿不能替代真实产品浏览器和材料检查。
- 回退：保留旧日期请求解释与旧包下载路径。实现未通过范围一致性门禁时回退本任务代码和新增资源，不重写或删除用户事实及历史材料。
- 交付：在 WSL 中用本机 HTTP 与应用内浏览器审阅；应用本身仍为可离线运行的本机程序。

## 8. 进入实施前

用户已确认方案 A；PRD 已按最终结构收敛，范围合同、分钟/快捷语义、旧材料版本兼容和执行顺序已明确，没有遗留产品问题。本版完整最终摘要已提交，用户后续明确回复“进入实施”；已运行 `task.py start`，可以派发实施。若评审后有实质范围变化，先更新方案并重新评审。

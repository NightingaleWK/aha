## 3. 验证矩阵

| 场景 | 必须证明的结果 |
| --- | --- |
| 起始秒、结束分钟、结束排他秒、相同/倒置/非法端点 | 实际成员和界面文案一致；错误不产生新预览或保存身份 |
| 当天、近 24 小时、近 7/14/30 天、本月、全部、自定义 | 快捷语义一致；跨日/月/闰日正确，无本机浏览器时区偏移 |
| 跟随时刻/固定结束；预览后保存；重新预览 | 每次分析只取一次 now，冻结后不漂移 |
| 仅明细、仅日汇总、混合、待核对、已占用、目标批次 | 实施 A；不跨粒度相加、不用全天金额冒充小时排除金额，不把零点投影当真实时间，不绕过独占 |
| 完整月、部分月、首尾部分日、一日内范围、同日不同时间游标 | 汇总与原始成员一致；无重叠分段，游标不能串用，查询利用索引 |
| 新建/当前修订/新旧冻结仅改用途/状态变更/版本 3 原包下载 | 范围参与应有校验；成员摘要算法不变；旧完整性未知值、原冻结语义和原包字节保留 |
| 项目搜索、动态增删/改名、回填、核对动态卡片 | 显示值、业务值、实际请求一致；无陈旧事件或失效浮层 |
| 键盘、外部点击、取消、dialog 内选择、长文字、禁用 | 焦点和反馈可操作；取消不清原预览，禁用不能绕过 |
| 1440/1366/1280/430/375，离线资源 | 字号、弹层边界和布局正确；资源从本机加载 |

按规范在隔离环境运行与修改相关的 unittest、Ruff、strict mypy、compileall 和 JavaScript 语法检查；最终全范围检查使用项目规定命令。真实页面验证通过 HTTP 发起，不以 Store 直调或交互稿截图代替。

性能先验证原整天路径和新增边界路径的 SQL 计划/VM 工作量；现有百万级夹具适用时复用并记录同机基线与新路径。不要把本任务设计阶段写成已完成规模测试。

# 适配 CC Switch 结构版本 26

## 目标

恢复 CCS 升级后的启动及手动同步，使新用量正常进入 aha，保留已保存台账，并交付可直接使用的桌面单文件 EXE。

## 背景与已确认事实

- 用户打开 aha 时遇到“CC Switch 结构版本 26 暂不支持；当前支持版本 23、24、25”，页面仍显示本地历史。
- `src/aha/domain.py:17,86` 的外部版本白名单只有 23、24、25；`src/aha/sources.py:37` 与 `src/aha/sql_dump.py:304` 共用此校验。
- 官方固定提交 `d0da1349f9403da228dc12a8f0f812e14f624d10` 的 25→26 迁移只补 MCP/Skills 应用开关；三张允许表的建表语句与既有 25 基准完全相同，Codex 会话导入器未修改。证据见 `research/compatibility-findings.md`。
- 2026-11-13 对本机默认 CCS 只读核查得到 `user_version=26`，三张允许表均不缺必要列；未读取配置、凭据、聊天正文或用量记录。
- Windows KnownFolder 返回实际桌面 `C:\Users\djsyw\Desktop`。本机基础解释器为 Windows x64 CPython 3.15.2 / SQLite 3.53.1；上一轮公开成品记录为 SQLite 3.53.4，构建时需核对运行时一致性并按实际情况补验。
- 用户已同意创建任务并继续规划，并在最终方案摘要后于 2026-11-13 明确回复“开始实施”，批准按本方案实施及交付。

## 需求

- R1：支持结构版本 26 的 CCS SQLite 数据库与完整 SQL 用量备份；启动同步、手动同步和 SQL 导入返回真实来源版本。
- R2：保留版本 23、24、25 的兼容行为；相同投影跨版本升级及重复导入不重复记账，不改变消费身份和内容指纹。
- R3：保持只读来源、必要字段检查、SQL 字面量解释及隐私边界；未来未知版本、缺表/缺列、伪造或矛盾版本声明继续拒绝。
- R4：保留本地历史、项目归属、报销占用和旧原包；内部投影仍为 23，应用库仍为 schema4，新材料仍遵守 manifest4，失败保留历史查询和最近成功进度。
- R5：提供与实际改动一致的中文 What’s New，完成适用自动及原生验收，交付与最终源码一致的桌面单文件 EXE；核实并清理任务自有临时文件。

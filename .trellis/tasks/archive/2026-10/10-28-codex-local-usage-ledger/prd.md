# Codex 本地用量台账与高效查询

状态：实施中。用户于 2026-10-28 以“实施”批准最终规划，授权按本版需求、设计和执行计划推进。

技术设计见 `design.md`，执行与回退顺序见 `implement.md`，子代理上下文见 `implement.jsonl` 和 `check.jsonl`。

## 目标与价值

将已采集的 Codex 用量长期保存在 aha 自有本地数据库，使项目查询、费用统计和报销不再依赖 CCS 当前保留的明细或逐份历史快照。数据增长时，常用查询、同步和导出的响应与内存占用仍有可验证的边界。

## 需求

### R1 采集范围与所有权

仅统计 Codex，沿用当前会话用量口径。CCS 与 Codex 仍为只读来源；必要用量及目录依据在本机处理，保持既有隐私、北京时间、Token 语义及精确金额口径。

### R2 同步触发与反馈

仅在打开工具时自动同步一次，另提供手动同步。取消此前讨论过的后台定时采集、关闭后静默采集机制及开机启动，保留现有页面与“退出程序”的使用方式。同步状态、最近成功时间及失败原因可辨识；重复点击不能产生并发重复采集或重复用量。

### R3 长期留存与真实覆盖

aha 保留已经成功采集的历史明细，CCS 后续清理不触发本地删除。未及时采集而已被 CCS 删除的明细只能保持来源日汇总及缺口说明，不能承诺恢复逐条记录。新台账建立后不自动删除已入账历史；一次性试用资料重建由 R8 单独约束。

### R4 身份、修订与冻结依据

相同用量重复同步不重复计数；来源内容改变时保留可追踪修订。日常查询采用校验后的最新值。新台账中形成的报销版本及材料保留当时依据，并能提示与当前数据的差异；来源重建、换路径或重复导入不得绕过新台账内的占用。旧试用报销不在此保留义务内。

### R5 明细与日汇总覆盖

历史明细和之后取得的日汇总不能重复累计。完整覆盖、部分覆盖、只有汇总或无法确定覆盖应可辨识；存在冲突时保留依据并提示核对，不通过比例分摊、差额造明细或静默选择来冒充完整数据。

### R6 本地查询与业务能力

用量列表、项目/日期筛选、日/月/模型统计、人工归属、可用用量与全部用量、报销保存及导出均以 aha 自有资料为依据。查询不触发 CCS 读取。保留报销生命周期、独占校验、幂等及新台账材料下载能力；CCS 历史来源依据可追溯。

### R7 并发安全与失败恢复

CCS 清理或写入期间，同步应取得一致的已提交状态，或明确失败。CCS 整轮重建可能分批提交，不能把一次合法快照等同于业务资料已全部重建完毕。锁等待和重试有上限；失败或无法核实的缩水/回退不能被解释为空数据，不能清空历史、推进成功同步进度或破坏报销占用。同步期间既有本地资料仍能查询。

### R8 历史用量保全与试用资料重建

用户明确尚未正式使用，授权清理除历史 CCS 来源资料外的试用业务数据。此决定替代此前旧业务兼容迁移的范围。

保留原始 CCS 活库、历史数据库和 SQL 备份。现有 aha 试用目录还含 CCS 用量快照，清理前先验证并保全其中可恢复的历史用量，避免删除原来源可能已清理的明细。无冲突且来源可确认的事实并入新台账；来源、修订先后或覆盖无法确认的候选保留依据并待核对。

新版本按干净业务库建立，不迁移旧试用项目规则、人工归属、报销、占用、财务状态、幂等、事件或 ZIP，不维护旧业务 schema 的运行期兼容分支。清理在实施阶段按路径清单执行：先只读盘点、确认旧程序已退出并做一次性可逆保全，再清理明确属于 aha 的试用资料；不得递归删除整个父目录或按数据库扩展名清理未知文件。源资料始终在保护清单，未知文件保留。

### R9 性能与交付验证

围绕真实查询和导出场景验证百万级与千万级明细下的查询耗时、同步增量、内存占用、数据库及证据材料增长。不得以数据库容量上限、索引存在、命令成功或少量测试代替性能结论。保持 Windows 本机工具的使用与交付方式。

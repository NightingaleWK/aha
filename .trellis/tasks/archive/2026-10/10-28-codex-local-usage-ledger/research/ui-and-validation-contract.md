# 页面、运行范围与验收依据

研究日期：2026-10-28。状态：规划研究；不是已实现行为、性能结果或 Windows 发布验收。

> 后续范围更新：用户明确尚未正式使用，允许清理除历史 CCS 来源资料外的试用数据。旧业务库、旧报销、旧占用与原 ZIP 的兼容迁移取消；只保全并安全并入历史 CCS 用量。下文早期对既有报销材料保留的描述仅对应研究时范围，新台账今后产生的材料仍须冻结。现行范围以 PRD 和 design.md 为准。

## 1. 本轮用户已确认

- 仅统计 Codex，沿用当前会话用量口径。
- 用量长期保存在 aha 自有数据库；业务查询不依赖 CCS 或每次解压全份快照。
- 同步触发仅为打开工具时一次、手动同步。用户撤回了此前的后台常驻、定时采集及可选开机启动方案；这些旧建议不再适用。
- 通过只读一致性视图处理 CCS 并发写入/清理；忙或超时可失败，旧数据和成功进度保留。
- 源库先清理了未被 aha 采集的明细时，只能保留来源日汇总，不保证恢复逐条信息。
- 重复读取不重复计数，部分/未知跨粒度覆盖保留依据并提示核对。
- 日常查询采用校验后的最新事实；既有报销版本与 ZIP 保持冻结，可显示差异。
- SQLite 为本次选型；用百万和千万级数据做性能验证。本轮只批准创建任务和规划，尚未批准实施。

## 3. 建议交互与状态合同（待最终规划评审）

- 页面先展示已发布本地台账；没有数据时显示本地空态。自动同步与手动同步共用同一管线。
- 同步卡片显示未同步/同步中/已完成/失败、最近成功时间、新增/修订/无变化数量。失败不把旧数据说成本次新成功。
- 查询主体绑定本地数据版本、归属版本与占用版本；同步暂存阶段不发布半批次。发布后提示并使依赖旧事实的预览失效，冻结报销依据继续可查。
- 查询和分页使用有界载荷与稳定游标；保存依据覆盖完整筛选范围，不以可见页为成员集合。
- 同步只允许一个有效运行者；其他页面显示同一运行状态或明确冲突，不另开一次。跨进程依靠资料库状态/事务与约束，不能只依靠前端 busy。
- 保留数据来源设置、SQL 导入、目录依据识别、项目管理和报销记录；不增加其他应用采集或任意来源自动合并。
- 未经证明的覆盖、源代际或修订顺序不能显示为已核对；具体台账并入与覆盖合同见另两份研究。

## 4. 性能验收应如何记录

这是新查询架构的验证计划，不是已有性能承诺。最终工作负载与量化门槛必须随设计一起评审。

- 规模：至少 100 万与 1000 万条合成明细；另含来源日汇总、修订、项目/会话分布和不同占用比例。
- 查询：单项目/全部项目、月/年/全期间统计、可用/全部视图、第一页与深页游标、冲突提示及目标批次自身豁免。
- 写入：首次导入、完全相同重同步、少量新增/修订、源清理后的再次同步、异常中断重启。
- 资源：P50/P95、首查与热缓存分别报告，记录进程 RSS 峰值、库/索引/修订/材料/WAL 大小及新增写入量。
- 并发：同步读取与暂存时，既有本地列表可查询；发布锁、占用竞争、取消退出及失败回滚需观察状态。
- 证据：解释器/SQLite 版本、硬件/系统/磁盘、合成种子、生成耗时、查询 SQL 与 EXPLAIN QUERY PLAN、测量命令与原始结果。冷进程测试不能冒称清空了系统磁盘缓存。
- 全量导出按选择规模独立测量，不能要求导出千万行和单页列表有相同耗时。内存必须分批有界，不把整个选择或 ZIP 同时读入内存。

## 5. 官方技术依据与运行时门禁

- [SQLite 适用场景](https://www.sqlite.org/whentouse.html)：桌面本地存储适用，单文件同时单 writer；本任务保持本地单机资料目录。
- [组合索引与查询规划](https://www.sqlite.org/queryplanner.html)：以真实谓词/排序和执行计划决定索引，不为每个字段机械加索引。
- [事务隔离](https://www.sqlite.org/isolation.html)：一致读取与忙错误需要正常处理，不能跨独立读取拼出不同时间的明细/汇总。
- [在线备份](https://www.sqlite.org/c3ref/backup_finish.html)：备份中来源变化可触发重启，busy/locked 和整体超时不能被当作空数据。
- [数值精度](https://www.sqlite.org/floatingpoint.html)：金额精确十进制口径不能退化为 REAL SUM；由存储研究给出实现路径。
- [WAL 第 11 节](https://www.sqlite.org/wal.html#walresetbug)：官方记录多连接同时写/checkpoint 的 WAL-reset bug，3.51.3+ 已修复，3.44.6/3.50.7 有回补。采用多连接 WAL 前必须核对实际运行时版本；Linux 检查与 Windows EXE 均记录，不能由 Python 大版本推测 SQLite 版本。

本轮仅对开发 host 执行了只读版本查询：`python3` 为 3.14.4，`sqlite3.sqlite_version` 为 3.46.1。它不是新架构可直接采用的已修复 WAL 基线，也不是用户 Windows 成品版本。实施时在任务隔离运行时中解决此门禁，不改全局 Python 或 CCS 运行时，不把该只读探测写成发布通过。

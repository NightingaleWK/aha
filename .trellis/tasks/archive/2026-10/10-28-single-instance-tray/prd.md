# 单实例重开与 Windows 托盘退出

## 目标

消除重复打开 aha.exe 造成多个后台服务、误关网页后找不到端口和退出入口的问题。用户通过再次双击程序或 Windows 托盘找回页面，无需记录端口。

## 背景与依据

以下为规划时的源码位置，实施后行号可能变化。

- `src/aha/__main__.py:69`、`:79`：每次 main 都创建服务，缺少启动前跨进程互斥；这是重复双击产生多个服务的入口。
- `src/aha/__main__.py:26`、`:45`、`:52`：每个资料目录只有一份 runtime.json，后启动者覆盖地址；run_id 仅防止旧实例退出时误删新描述符。
- `src/aha/server.py:494`、`:582`、`:609`、`:621`：只绑定 127.0.0.1，已有按端口命名的 Cookie、Host/Origin/CSRF 和启动地址认证。
- `src/aha/web/app.js:795`、`:808` 与 `src/aha/server.py:205`、`:229`：启动同步由页面初始化请求，服务按同一生命周期去重；CLI 创建服务不会直接开始同步。
- `src/aha/server.py:731`、`src/aha/web/app.js:938`：页面已有显式退出；`src/aha/server.py:110`、`src/aha/storage.py:247` 负责取消工作和关闭连接，目前没有托盘所有者。
- `scripts/build_windows.py:107`、`:108`：Windows 使用无控制台目录包与 OneFile；验收不能用任务管理器中的 PID 数替代服务实例数。

## 需求

| ID | 需求 |
| --- | --- |
| R1 | 同一本机资料目录同时只有一个新版 aha 服务拥有运行权。连续/并发启动、另一份 EXE 和受支持的目录别名不得绕过；不同资料目录可独立运行。 |
| R2 | 重复打开仅验证并打开已有页面，随后结束临时启动，不另建 Store、服务或托盘，不重复已有启动同步；尚未打开过页面的服务仍可在首次打开时触发首轮同步。 |
| R3 | Windows 默认显示托盘：双击打开页面，右键提供“打开 aha”“退出程序”；操作只作用于该实例。任务栏外壳重建后恢复图标。 |
| R4 | 关闭全部网页、刷新和多标签切换不退出程序；再次双击与托盘都能找回页面，无需记录地址。 |
| R5 | 页面和托盘共用幂等的显式退出流程：停止新业务、取消或完成工作、关闭资料与端口、清理本次描述符和托盘，最后释放运行权；保留已保存台账和原包。 |
| R6 | 首个实例正在启动/退出时其他启动有限等待；新版崩溃或陈旧运行文件不永久阻止重启。持锁但无法确认状态时明确失败，不抢占、不强杀、不另起服务。 |
| R7 | 保持自动端口、默认资料位置、本机认证和启动输出。保留 --data-dir/--port/--no-browser，提供显式无托盘 CLI 模式；Linux 保持无托盘。凭证不进入公开消息、托盘、Git 或材料。 |
| R8 | Windows 目录包与 OneFile 分别验收；真实浏览器证明重开与同步去重，原生桌面证明托盘操作，不以 mock 代替原生验收。 |

## 验收标准

| ID | 对应需求 | 可观察结果 |
| --- | --- | --- |
| AC1 | R1、R2 | 同一隔离目录连续启动及同时启动至少 5 次，只有一个持有运行权的服务、一份托盘；复用启动成功返回，地址和服务身份一致。换 EXE 位置与常见目录拼写/别名重做后仍成立。 |
| AC2 | R2、R4 | 首次打开、刷新、关闭全部标签后再双击、托盘打开及双标签访问同一份资料，同一服务生命周期最多一轮启动同步；手动同步仍可用。--no-browser 后首次打开可以触发尚未执行的首轮同步。 |
| AC3 | R1、R3、R7 | 两个 data-dir 同时运行，Cookie 不互相覆盖；退出其中一个后另一个的页面、端口和托盘继续正常。 |
| AC4 | R3、R8 | Windows 目录包和 OneFile 均可通过托盘双击打开、菜单退出；受控 TaskbarCreated 消息证明图标恢复，不为测试重启用户 Explorer。 |
| AC5 | R5 | 页面退出、托盘退出和同时请求退出均清理端口、描述符、托盘与运行权；同目录可重启，项目和指定历史 ZIP 内容/摘要保留。 |
| AC6 | R5、R6 | 同步中退出、启动未就绪时并发打开、退出未完成时重开，不出现第二个写入实例、半批次资料或提前释放运行权。 |
| AC7 | R6 | 自有实例终止后可重启；覆盖残留 runtime、PID 复用、坏 JSON、失效端口与非 aha 端口。持锁但身份不可验证时有限失败，不打开外部地址或结束无关进程。 |
| AC8 | R6、R7 | 资料不可写、端口占用、托盘初始化失败和浏览器打开失败有安全可操作反馈；启动失败清理已获得资源，浏览器失败仍可通过已工作的托盘重试。 |
| AC9 | R7、R8 | 无浏览器/无托盘 CLI 回归通过；实例识别继续要求本机认证，不削弱 Host/Cookie/Origin/CSRF。报告、截图和材料不含启动凭证。 |

## 范围外与兼容边界

- 不做关网页自动退出、周期采集、开机自启、远程访问、完整原生窗口或资料库 schema 迁移。
- 首次升级先退出旧版；旧 EXE 无法被新互斥协议反向约束，不扫描或批量结束遗留未知进程。
- 不为恢复启动删除台账、原包、CCS 来源或未知业务文件，不扩大旧试用资料清理脚本的白名单。
- 使用小型合成资料验收，不新增百万/千万规模复测。

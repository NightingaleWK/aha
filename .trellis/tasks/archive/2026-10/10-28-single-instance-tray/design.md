# 技术设计：单实例重开与 Windows 托盘退出

## 1. 职责边界

产品行为与验收以 [prd.md](prd.md) 为准；本文件规定计划实施的约束。

| 模块 | 计划职责 |
| --- | --- |
| `src/aha/instance.py`（新增） | 目录规范化、操作系统锁、描述符、限定回环地址的身份核验与复用决策。 |
| `src/aha/runtime.py`（新增） | 拥有服务线程、退出状态、托盘适配器和清理顺序，提供幂等退出入口。 |
| `src/aha/tray_windows.py`（新增） | ctypes/Win32 隐藏窗口、通知区图标、菜单、消息循环和资源销毁。 |
| `src/aha/__main__.py` | CLI、复用/新建分流、浏览器与安全启动错误，保留较薄入口。 |
| `src/aha/server.py` | 认证后读取实例身份，页面退出转发统一生命周期。 |
| `src/aha/web/app.js` | 保持页面首次启动同步去重，仅调整必要的退出状态与文案。 |
| 打包/文档/测试 | 内置托盘图标，包含新模块/资源，更新运行契约并验证完整链路。 |

不把运行锁放进 Store 构造器：其独立连接/进程事务测试仍然有效；生产启动运行权由 CLI/runtime 层负责。

## 2. 运行权与启动竞争

按既有默认位置选择 data-dir，创建目录，resolve 与 Windows normcase 统一常见别名。在实际资料目录打开持久 `.instance.lock`，不截断、不在退出时删除锁文件。Windows 用 msvcrt.LK_NBLCK 锁定固定字节，Linux 用 flock(LOCK_EX | LOCK_NB)；句柄不继承给外部子进程。

先取得锁再创建 Store/HTTP；锁覆盖初始化、运行与全部清理。文件存在不是占用依据，只有明确锁冲突才解释成已有实例，权限/路径/系统调用错误须报告。

```text
选择资料目录 → 尝试取得锁
  ├─ 成功 → 检查旧格式活动记录 → 创建服务/托盘 → 发布 ready 描述符 → 打开页面
  └─ 冲突 → 有限等待并读描述符 → 认证核验身份和 ready → 打开原页面 → 临时启动退出
                       └─ 期间取得锁 → 回到新建流程
```

等待共享 monotonic 截止时间，默认总计最多 10 秒，单次网络核验最多 1 秒。持锁但无描述符、尚未就绪、正在退出或无法核验时不覆盖描述符、不新建 Store。超时提示正在启动或退出、稍后重试；持续无响应时先退出原程序。

取得锁后，旧格式记录若指向可能存活的旧版则明确要求先正常退出，不接管资料或补装托盘。新版遗留描述符以操作系统锁为权威，PID 被无关进程复用不能单独阻止恢复；不按 PID 杀进程。

## 3. 描述符和实例身份

保留 runtime.json 原子写入/replace 与只删除本次 run_id 的语义。计划字段：descriptor_version=1、application="aha"、protocol_version=1、pid、run_id、profile_id、bootstrap_url。run_id 与 Application.launch_id 一致，profile_id 为规范化目录身份摘要。

服务能够接收请求且必要托盘已建立后才发布描述符。读取限制文件大小、字段类型和协议版本；未知版本不可当作陈旧文件覆盖活动所有者。

新增认证后的 `GET /api/instance`，沿用 `_boundary` 和 `_authenticated`，仅返回 application、protocol_version、run_id、profile_id、state（ready/stopping），不读 Store、不返回资料路径或业务内容。

复用客户端直接用 http.client，不依赖代理或任意重定向：

1. 地址只允许 `http://127.0.0.1:<合法端口>/?token=<非空单值>`；拒绝其他主机、用户信息、片段、额外路径/查询。
2. 请求启动地址换取 Cookie，只接受预期的同源 `/` 重定向和正确 Cookie；不跟随外部 Location。
3. 认证读取实例接口，比对协议、run_id、profile_id 和 ready，再将已验证地址交给浏览器。
4. 不请求同步，不修改已有 token、launch_id 或描述符；不能仅凭 PID、端口或 HTTP 200 断言 aha 正在运行。
5. 旧格式有独立识别分支，不能降级成任意本机 JSON 都可复用；可能存活且无法确认的旧版要求先退出。

复用成功返回 0；`--no-browser` 只省略打开，仍可输出原 AHA_URL。`--port` 只作用于新建，复用沿用原端口。窗口模式打开失败使用安全原生反馈，不公开完整 token 地址。

## 4. 统一退出

控制器管理 starting → ready → stopping → closed。Windows 主线程处理托盘消息，HTTP 服务在受控线程；Linux/--no-tray 等待同一服务生命周期。

- 页面认证退出、托盘退出、KeyboardInterrupt 调用同一个幂等入口，置 stopping 与取消事件；不在 serve_forever 自身线程中调用会等待自己的 shutdown。
- stopping 后拒绝新业务写入，已接收事务完成或回滚，有限来源工作收到取消；不得提前关闭仍在使用的资料连接。
- 停止 HTTP 接收，等待请求和同步所有者退出，关闭 Application/Store 与端口；向消息线程投递清理事件，移除托盘并销毁窗口；删除本次描述符，最后释放锁。
- 不用 taskkill/os._exit 满足时限；有清理工作时不能提前放锁或报告已完整退出。
- 页面仅在退出请求被接受时显示“正在退出程序，已保存资料会保留”；请求成功不能替代最终端口/锁/进程验收。
- 初始化失败反向清理已创建资源。默认托盘初始化失败明确报错并退出，避免留下无入口服务；浏览器失败保留已可用的托盘供重试。

继续由页面初始化触发首轮同步并由服务去重，不在新生命周期中提前读取来源或增加周期任务。

## 5. Windows 托盘

采用标准库 ctypes 与原生 Win32 API，避免为两个菜单项引入 GUI 框架。

- 隐藏顶层窗口接收 Shell 通知；不用无法接收广播的 message-only window。显式定义 64 位指针/句柄、Unicode API、回调签名与回调寿命。
- Shell_NotifyIconW 添加/删除图标；双击/键盘激活打开，右键“打开 aha”“退出程序”。回调只转发事件，不阻塞网络或 Store 清理。
- 提示用简短资料目录名称区分实例，不展示凭证、端口或完整私有路径。新增沿用 mark.svg 形象的内置静态 ICO，并纳入包资源和两个构建入口。
- 注册 TaskbarCreated，幂等重建图标；自动检查用受控消息注入，不重启用户 Explorer。
- 结束时清理自有菜单、图标与窗口；页面退出也执行同样流程。
- 增加 `--no-tray` 供无桌面 CLI/检查明确跳过；`--no-browser` 不隐含无托盘。Linux 不加载 Win32 模块，--no-tray 为无操作选项。

## 6. 兼容、风险和回退

- 无数据库迁移，不改变来源、核算、冻结原包与业务目录内容；运行文件不进入材料。
- 实施完成后更新规范中的旧“无托盘”事实，继续保留无周期采集/自启的约束。
- 首次升级先退出所有旧版；无法反向约束旧 EXE，也不扫描/批量结束未知进程。
- 锁文件必须保留；旧试用重建工具将它视作未知保留项，不扩大清理白名单。
- OneFile 可能有 bootloader 父子进程，按服务身份、锁和端口验收，不承诺只显示一个 PID。
- ctypes 布局、菜单、目录别名和资源清理须真实 Windows 验证；Linux mock 仅证明适配器交互。资料支持本机目录，网络盘/跨主机共享不在本次范围。
- 回退前显式退出新版本，确认锁释放后使用原版本和同一 schema3 资料；不删除业务库。旧版恢复其原有多实例行为。

API 依据见 [研究记录](research/runtime-lifecycle.md)。技术验证安排在执行计划中，本文不是已执行的验收证据。

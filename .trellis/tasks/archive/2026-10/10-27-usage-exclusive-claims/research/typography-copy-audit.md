# Research: 界面字号与操作文案

- Query: 保持现有 teal / 深色导航风格，改善整界面可读性，用直接的业务名称替换口号和实现术语。
- Scope: internal；仅排版和文案建议，不改交互架构或产品代码。
- Date: 2026-10-27

## Findings

### 1. 现状与范围

`src/aha/web/style.css:1` 的根字号为 14px；主要选择器内还单独设定表格 11px、表头 10px、次行 9px、按钮 12px/small 11px、输入 12px、标签 11px，移动断点再次使用 9–11px。因此只调 root 不能解决问题。中文标题负 letter-spacing 也增加了拥挤感。

当前文案主要位于 `src/aha/web/index.html`，动态标题/通知/空态位于 `src/aha/web/app.js`。代码模式锚点：`app.js:31` 通知、`:99` 空态、`:229` 项目空态、`:408` 用量空态、`:481` 创建成功、`:508` 报销空态、`:536` 版本详情、`:550` 下载/修订按钮。

保留配色、卡片、左导航、页面结构和本机资源。中文页面不再重复放英文 eyebrow；logo 的品牌字形可保留，不将正常中文文本压缩为装饰字。

### 2. 可执行排版基线

建议统一文字变量后逐项替换现有硬编码；值使用 rem，继承缩放，不能留下旧的 9–12px 覆盖：

| 用途 / 选择器示例 | 建议字号 | 行高与布局 |
| --- | --- | --- |
| 正文、段落、空态说明、notice、dialog intro | 16px / 1rem | 1.6；正文 400，普通说明也保持可读 |
| 表格 td、目录列表、报销记录内容 | 15px / .9375rem | 1.6；单行 td 上下 12px、左右 16px；项目/说明允许换行 |
| 表头 th、字段标签、指标标题 | 14px / .875rem | 1.5；500–600，不靠浅色和微小字号制造层级 |
| 按钮、tabs、text-button、chips | 15px / .9375rem | 1.4；主要按钮至少高 44px，次按钮至少高 36px；small 只减留白 |
| input/select/textarea | 16px / 1rem | 1.5；单行至少高 44px，padding 约 9px 12px；textarea 至少 3 行 |
| 次要文字、subline、tag、状态、页码、field-help、元数据 | 13px / .8125rem | 1.5–1.6；任何断点保持此下限，重要反馈采用正文级别 |
| h1 / h2 / h3 | 28px / 20px / 17px | 1.35–1.5；中文 letter-spacing:normal，600 左右 |
| 指标数字 | 30–32px | 1.3；tabular-nums；窄屏可到 28px，不缩成表格字号 |
| 导航 | 桌面 16px，紧凑横导航 14–15px | 文字清晰，操作区至少 40px；保留现有图标与选中态 |

保持系统字体栈（Segoe UI / Microsoft YaHei / system-ui），不引入在线字体。数字右对齐、日期尽量不拆到字符；日期时间可分两行。长项目名和目录允许正常换行，路径次要但仍至少 13px。表格溢出在 `.table-wrap` 内滚动，不缩小字体来塞入所有列。

响应式仍沿用现有约 1180 / 900 / 600px 断点：过滤器从多列变两列，金额/说明变单列，按钮区允许换行，dialog 内可滚动。窄导航可用短名称“用量 / 项目 / 报销”，accessible name 保持完整；不要把所有导航正文降到 10–11px。900px 图标侧栏若隐藏文字，须保留可访问名称和 tooltip，不把 font-size:0 当作可见文字的排版。

### 4. 状态、占用与生命周期文案

| 场景 | 建议文字与可见动作 |
| --- | --- |
| 新建范围 | 可用用量；全部用量（查看） |
| 占用说明 | 已排除其他报销记录占用的用量。查看占用记录 |
| 排除计数 | 已排除：N 条明细、M 条历史汇总；历史汇总代表数量单独标注，避免把两种粒度混称 N 条明细 |
| 明细状态 | 可用；已占用（AHA-…）；待核对 |
| 有效版 | 当前记录；历史版本 |
| 业务状态 | 草稿；已提交；已报销；已作废；待核对 |
| 旧资料冲突 | 这条记录与其他记录使用了相同用量。请先核对重复记录。 |
| 旧资料处理 | 查看冲突记录；确认保留此版本；作废此记录；原因字段必填 |
| 已提交操作 | 撤回为草稿；提示：撤回后可修改，用量仍由此记录占用。 |
| 作废操作 | 作废记录；原因标签：作废原因；确认按钮：确认作废 |

| 已报销纠错入口 | 作废记录；帮助：更正已报销记录，请先作废，再新建报销记录。 |

参考成本和人工申请金额保持两个独立字段，币种始终可见。可在参考成本旁的帮助中统一解释“按 CC Switch 已保存金额汇总；申请报销金额由你填写”。避免在顶部、黄色横幅、页脚、弹窗同时重复“不是官方账单、原件未改”等说明；必要来源口径保留在材料说明和帮助内。

### 5. 空态与反馈

| 场景 / 旧表达 | 建议表达 |
| --- | --- |
| 从一份用量数据开始 | 尚未加载用量；读取 CC Switch 数据，或导入备份。 |
| 先建立一个项目 | 暂无项目；新建项目并选择它的工作目录。 |
| 还没有报销批次 | 暂无报销记录；在“用量与费用”选择项目和日期后保存。 |
| 空结果也可保存为如实标明的材料… | 所选条件没有可用用量；调整项目或日期，或查看已有报销记录。 |
| 全部匹配量均已占用 | 所选用量已被占用；查看占用记录。 |
| 读取成功，必要用量与目录依据已留存。原件保持原样。 | 已加载用量。 |
| 归属已保存长说明 | 已更新项目归属。 |
| 批次 · vN 已保存为草稿并下载… | 已保存报销记录，材料已下载。 |
| 状态已更新，原证据包保持不变… | 已标记为“已提交 / 已报销”。 |
| 新增撤回成功 | 已撤回为草稿，可以修改。 |
| 新增作废成功 | 已作废，用量已释放。 |
| 缺少原因 | 请填写作废原因。 / 请填写撤回原因。 |
| 保存时别人抢先占用 | 可用用量已变化，请更新预览后重试。；提供“更新预览”动作 |
| 保存成功但下载失败 | 记录已保存，下载失败。请在“报销记录”中下载材料。 |
| 读取失败 | 无法读取数据，请检查文件或选择其他备份。 |
| 程序已退出，端口将释放… | 程序已退出，可以关闭此页面。 |

成功信息先给结果，只补当前需要的下一步；失败给可执行动作。后端仍保留安全错误码，普通用户提示不展示端点名、栈、写入协议、数据库版本、内部哈希等字段。

### 6. 浏览器验收，不增加 CSS 镜像单测

1. Windows 原生浏览器 100% 下检查 1440×900、1366×768；补 1024×768、768×1024、430×932、375×812，覆盖现有断点两侧。用相同真实来源与长项目名检查三主页面、表单、空态、确认弹窗和待核对状态。
2. 检查实际计算字号：body/notice/input 为 16px；td 为 15px；th/label 至少 14px；按钮至少 15px；subline/tag/field-help/页码至少 13px。所有可见普通文本都检查，图标/明确隐藏文本单独排除；不能只检查 root。
3. 另在真实浏览器检查 150% / 200% 缩放，确认操作仍可达。deviceScaleFactor 只改变像素密度，不作为页面缩放验收的替代。
4. 根页面不横向溢出；宽表只在表格容器滚动。长名称、目录、金额、日期不遮住按钮；dialog 标题和确认按钮可见或可滚动到达；窄屏 CTA 不靠缩小文字容纳。
5. 草稿→修改→保存、提交→撤回、报销→作废、占用冲突和待核对处理中的按钮文字与行为逐项对应。旧历史仍可下载，文案不能暗示覆写材料或重复报销。
6. 截图保存普通桌面、窄屏、修改/作废弹窗和冲突状态；检查 computedStyle 与真实渲染，不以搜索源码是否存在 16px 代替验收。不改变金额算法或导出协议来配合 UI。

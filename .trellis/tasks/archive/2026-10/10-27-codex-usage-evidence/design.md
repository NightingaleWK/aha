## 架构与写入边界

这是一个贯通取证流程，项目归属、读取、留存、筛选、预览、批次与四种导出共享来源及金额契约。重新评估 O1/O2 后，仍以一件 Windows 工具的贯通交付验收，不为内部模块另建父子任务；按存储、业务、界面、成品顺序实施。选用 Python 3.12+ 标准库及原生 HTML / CSS / JavaScript；压缩会话头使用固定版本 `zstandard` 并随成品打包。Windows x64 原生构建，双击后打开本机浏览器，程序提供退出入口。

## 来源适配与一致快照

默认 Windows `%USERPROFILE%\.cc-switch\cc-switch.db`，也可选择其他 SQLite 文件或 CCS SQL 备份。一次仅使用一份来源，不自动合并 Windows / WSL 数据。

SQLite 用 URI `mode=ro` 打开并开启查询只读，在有界超时内通过 backup API 取得一致内存快照；验证结构版本 `23` 和必需列，再投影允许字段并关闭全库快照。禁止迁移源库、改变 journal 模式、checkpoint、以 immutable 读取活跃源或仅复制主文件。忙、损坏、不兼容时明确失败，建议用户主动改用 SQL 备份，不静默读其他库。

SQL 接受 UTF-8 / BOM，首期上限 128 MiB。小型词法解释器支持 CCS 的带列名 INSERT、多行 VALUES、字符串双单引号转义及内容中的逗号、换行、分号。只解释 `proxy_request_logs`、`usage_daily_rollups` 和所需 `model_pricing` 的常量值，写入应用自己的结构；不执行输入提供的建表、表达式、函数或 SQL 程序。跳过其他配置表；必要数据格式非法、版本不支持或主键冲突时失败，不能吞掉异常后报成功。

成功加载后生成可持久恢复的 `capture_id`，关联不可变用量投影与目录依据快照。SQL 保存原文件 SHA-256；SQLite 保存允许字段投影的指纹，不能称其为原 `.db` 哈希。记录源文件名、结构版本、读取时间、最新事件、观察覆盖和日汇总时区假设。用量原文件的绝对路径不进入留存或分享包；项目目录依据可在应用自己的私有数据中持久化，不写进分享材料或普通日志。

## 历史留存和存储事务

`storage.py` 唯一管理 `%LOCALAPPDATA%\aha\aha.sqlite3` 和应用自有文件目录；其上分别由 archive、projects、batches 承担业务，不在各模块重复建库。开发测试使用隔离 data-dir。

允许字段的规范 JSON 以 gzip 不可变对象保存，索引、来源观察、项目规则、人工归属和批次保存在 SQLite。用量及目录依据各有内容身份，相同内容复用对象，读取时间保留为来源观察；已存在对象只做校验，不覆盖。原库全量内存快照在投影后关闭，不将凭据写盘。

保存顺序为临时写入、校验、原子落位、提交索引；失败或崩溃留下的未完成对象不显示为可用。读取校验内容哈希、内部格式与版本，损坏时不改读最新源冒充历史。首次建立应用结构时不接触 CCS 结构；应用数据目录不可写时明确失败，不假称留存成功。

“历史留存”支持列表和选择，分析始终只消费一份 `capture_id`。不同快照不叠加，同键不同内容保存版本，不静默修正旧证据。第一版不跨快照拼接、相减或替代日汇总；源工具清理后可以重开已经保存的一份，不保证从未读取的明细恢复。退出仅清理内存和临时对象，既有留存与批次持续保存，首期不自动清理历史。

## 项目对象、目录规则与本地持久化

`Project` 使用稳定 UUID，保存名称和说明；例如 `liuying-流萤-运维管理平台`。`DirectoryBinding` 保存项目 ID、用户所选目录和规范化路径；一个项目有多个绑定。已发现的会话目录以列表供用户勾选，也可直接填写路径，不要求 Linux 历史目录在当前 Windows 文件系统存在。

通过 storage 管理的本地库保存项目、规则、人工归属及递增的 `classification_revision`。事务保存，写入失败明确报告，不假称规则已保存；不往 CCS / Codex 数据库加列或写数据。

路径匹配由 `projects.py` 唯一负责：Windows 去扩展路径前缀、统一分隔符并按 Windows 大小写规则规范化；Linux 区分大小写。每个绑定匹配自身和子目录，比较完整路径段，最长匹配优先；同一规范化目录重复绑定到不同项目必须拒绝。`/a/foo` 不匹配 `/a/foobar`。Windows / WSL 别名与同名仓库不得仅按末级目录合并，用户可把多个真实路径显式绑定到一个项目。

归属优先级为有效人工指定、目录规则、未归属。每条明细至多有一个 `project_id`，标记 `manual` / `directory_rule` / `unassigned` 来源。人工指定以来源记录 ID 和内容指纹绑定，防止同 ID 指向变化内容时误沿用；可对选定会话的全部明细批量指定。人工归属优先于后续目录规则更新，也可清除后重新按规则识别。

目录规则对当前已有明细和后续新数据均生效。任何项目、目录规则或人工归属修改递增版本并使旧分析失效；导出冻结项目名称与归属结果，已有文件不被更新规则改写。完整日汇总可按其来源复合键人工指定项目，不自动分摊或从日期推断。

## Codex 会话元数据

默认 `%USERPROFILE%\.codex`，允许另选元数据根目录；这只补充目录线索，不合并多份 CCS 用量。按所需会话 ID 查找 `sessions` / `archived_sessions` 的 `.jsonl` 和 `.jsonl.zst`，有界读取头部 `session_meta` 的 ID、cwd 和必要父标识，不解析聊天正文。当前索引仅辅助定位；原日志头优先，重复文件相同元数据合并，冲突或缺失进入待确认。

`zstandard` 作为固定版本运行依赖支持 Python 3.12 的流式解压，限制解压窗口、头部字节及扫描量，不能全文件解压。缓存只保存所需元数据并以文件状态校验，失效后重新读取；压缩归档、文件搬移和索引过期不得悄悄丢掉相关会话。

会话头 cwd 表示目录依据，不保证会话每轮业务内容都属于该目录；跨项目会话通过人工纠正解决。没有元数据也能读用量并人工归属。元数据指纹和识别覆盖计入分析身份；刷新元数据后原项目筛选分析失效。

提取后的必要目录依据随历史留存保存，日后原日志搬移或删除仍可使用。补充元数据产生新的关联快照，不原地修改已经被批次引用的留存。

| `ProjectAssignment` | 项目 ID、归属来源、规则版本及必要的人工指定身份 |
| `ClaimDraft` | 选中项目的名称快照或全部/未归属标签、用途、可空申请金额字符串、CNY / USD、金额说明 |
| `AnalysisResult` | 所选 capture、日期/项目筛选、归属版本、明细、历史汇总、每日/模型聚合、精确合计和覆盖/价格提示 |
| `ClaimBatch` / `BatchRevision` | 稳定批次、不可变版本、记录集合、冻结分析/说明、人工状态与证据包 |

日期转换为 `[起日00:00, 止日次日00:00)` Unix 范围；使用明确的 +08:00 业务偏移，不依赖主机时区或 Windows 是否安装 IANA 数据。首期不提供时分秒筛选，也不按小时分摊历史日汇总。

仅纳入 `app_type='codex' AND data_source='codex_session'` 明细，以及 `app_type='codex' AND provider_id='_codex_session'` 日汇总。其他应用和代理记录不叠加，避免混合来源双计；付费通道仍需人工说明，项目由用户配置目录关系或人工指定。

先为来源记录求得唯一归属，再同时按项目和日期过滤。全部项目包含未归属；指定项目只纳入有效归属该项目的记录，未分配的旧日汇总不进入指定项目合计。各项目和未归属的并集等于全部记录，互不重叠。

没有记录的日期不证明零消耗；日汇总缺少原时区字段，以北京时间作为明确假设。若同日同模型同时有明细和日汇总，保持原始粒度、按来源金额合计并标记混合来源待核查，不猜测删行或重建历史。

申请金额非空时验证非负、有限、最多两位小数并要求说明；空与零区分，不自动填参考成本，不设与套餐实付的隐含比例，也不自动换算汇率。

## Token 与金额规则

复现上游 `sql_helpers.rs:30-83`：语义 `0` 满足条件时减缓存读，语义 `1` 满足条件时减缓存读写，语义 `2` 原样。异常值依上游保留原始输入并标记异常。总 Token 为新增输入、输出、缓存读、缓存写之和。

金额从文本进入 `Decimal`，拒绝非有限或非法值。沿用来源总额，保留分项和倍率；不按现价重算历史。模型无可用价格且保存金额为零时标“未定价”，不解释成免费；非零历史金额但现价缺失时保留金额并说明价格依据缺失。

API 金额一律为普通十进制字符串；前端只展示服务端结果。卡片可以显示两位，CSV 保留有效精度，说明页给出精确值或明确舍入值；不把逐行先舍入的金额相加。

## 界面与状态

中文界面设“项目管理”“用量导出”“报销记录”入口。项目管理维护项目和目录；用量导出选择当前读取或历史留存、项目和日期，填写用途/申请金额，预览每日、模型与明细，可修正待确认归属，再“创建批次并下载”。报销记录查看版本、重新下载和手动更新状态。显示识别覆盖及未归属量，技术细节放在展开说明中。

默认当天，快捷选择近 7 天、本月、自定义日期。日期、项目、当前/历史留存切换均使预览失效；元数据或归属规则变化也清除当前结果。已保存批次版本独立保留，不因当前预览失效而消失。用途与申请金额不改用量，创建版本时冻结；分页不截断导出。

加载和下载显示状态并防止重复触发。空结果显示所选期间和零条匹配，允许导出如实标明的空材料。导入失败不得用旧结果冒充新来源；错误可操作，不暴露输入 SQL、凭据或堆栈。

服务仅绑定 `127.0.0.1` 可用端口，只提供内置资源，无 CDN / CORS / 目录浏览。每次启动生成随机访问凭证，API 校验凭证、Host / Origin、请求大小和路径；日志不记录 POST 内容、路径与凭证。退出关闭服务并清理内存，不删除已留存资料；关闭浏览器标签与退出程序的区别在界面说明。

## 报销批次和重叠提醒

批次使用稳定 UUID 和本地编号；每个版本冻结 capture、日期/项目选择、归属结果、记录集合、参考成本、用途及人工申请说明。首次创建为草稿版本。修改内容形成新草稿版本，旧版本内容、状态和文件不改；相同版本再次下载原 ZIP，不新建申请。

版本的草稿、已提交、已报销由用户手动更新和纠正，生成/下载不自动代表提交或收款。创建、修订和导出有服务端幂等键，重复点击或网络重试复用原结果。

重叠检测排除同一批次内部版本；明细按来源请求身份查交集，人工换项目或来源重定价不改变这一身份。日汇总及明细/日汇总跨粒度使用共同覆盖维度提示可能重叠；疑似键重建只提示，不自动去重。草稿与已提交/已报销分别显示，单纯同日不报确定重复。用户可查看、重导或继续，不自动扣减、不强制拦截。

本地保存冻结结果、成员、原 ZIP 及校验和；下载旧版本不重新查询源库或应用当前规则。原包丢失或损坏明确报错，不把新生成的不同包冒充旧包。完整身份、状态和异常契约见 `research/retention-batch-contract.md`。

## 输出契约

ZIP 名为 `项目_起日_止日_批次编号_v版本.zip`，处理 Windows 禁用字符、保留名和长度。同版本原文件不重写，浏览器处理重复下载的本地名称。包内：

1. `使用明细.csv`：项目 ID/名称、归属来源、含偏移的时间、模型、原始输入/语义、新增输入、输出、缓存读写、金额分项/总额 USD、倍率、来源记录/会话 ID、价格依据状态。只含真实明细，不加伪造汇总行。
2. `每日汇总.csv`：项目 ID/名称、日期、模型、明细数、历史汇总代表记录数、来源粒度、四类 Token/总 Token、参考成本 USD。与期间预览同口径。
3. `费用说明.html`：项目用途、期间、来源、参考成本及构成、已填写申请金额/说明、覆盖/未定价提示、批次编号/版本和生成时间。报销状态为本地人工管理，不把它写成官方付款确认。自包含可打印样式，按数据自然换页。
4. `导出信息.json`：应用/清单版本、capture/来源观察、用量/元数据指纹、源文件名、结构版本、日期/时区/项目筛选、冻结名称/归属版本、批次编号/版本/成员、上游参考提交、价格口径、覆盖/未归属行数、申请说明、前三个文件 SHA-256；不保存完整目录规则或制造清单自身的循环哈希。后续人工状态改变不改原 ZIP。

CSV 使用 UTF-8 BOM 和标准引用，用户文本防止公式执行；HTML 对用户和来源文本转义。请求 ID 不冒充官方流水号。浏览器下载到用户选择的位置，不自动覆写 OneDrive；付款凭证由用户与证据包一并归档，首期不上传/内嵌附件。

# Codex 用量导出与报销证据工具

## 目标与用户价值

在 `aha` 中制作独立的 Windows 本地小工具，帮助用户管理项目目录、留存 Codex 用量、按项目和日期导出费用证据，并记录报销批次，便于公司项目 AI 费用报销与后续复查。CC Switch 源码是数据解释依据，不修改 CC Switch 本身。

## 背景与已确认决定

- 用户自费购买 GPT Pro 100 订阅，将 CC Switch 用作本地用量监控。公司需要期间费用及其证据，用户接受人工判断项目归属。
- 现有材料按项目保存在 `C:\Users\djsyw\OneDrive\知识库\工作\AI 费用记录`，包括 CCGO 用量 CSV 和其他供应商金额、成本 CSV。新工具延续按项目、期间归档的习惯。
- 用户于 2026-10-27 同意创建任务并先规划；随后以“按你说的”确认：CCS 参考成本作为使用证据，申请报销金额、币种与说明由用户另填，首期不自动分摊订阅实付。
- 用户进一步确认首期加入项目对象：例如创建 `liuying-流萤-运维管理平台`，手动选择多个属于它的目录，后续依目录规则自动归类并按项目导出。目录关系由用户设定，命中规则的记录不要求逐条再批准。
- 用户随后以“好的”确认首期加入必要明细留存与报销批次；规则影响预览、付款凭证附件、规则备份恢复仍是后续候选，不随本次确认加入。
- 用户将成品设计交由本会话提出。本版采用双击启动的 Windows 程序和本机浏览器界面；最终方案已批准，实现及验证结果见 `verification.md`。
- 所给 SQL 数据库版本为 `23`，有 10,852 条 Codex 明细（北京时间 2026-09-28 至 2026-10-27）、110 条 Codex 日汇总（2026-06-17 至 2026-09-24）。源码锚点、校验和局限见 `research/source-findings.md`。
- Windows `%USERPROFILE%\.cc-switch\cc-switch.db` 已在原生 Python 下只读确认版本 `23` 及必要表；WSL 另有独立数据库，不自动合并。环境依据见 `research/runtime-and-delivery.md`。
- CCS 成本为模型计价估算，会话日志不能单独区分官方订阅与中转站。旧数据可能只有日汇总，现价表不必然等于历史计价；截图与备份也不是同一截点，不能直接要求总额相等。

## 首期需求

### R1：独立运行与来源读取

双击 Windows x64 程序打开本机浏览器界面，不要求用户安装 Python、Node、数据库服务或部署网站。默认只读加载 Windows CCS 库，也可选择其他 CCS SQLite 文件或导入 SQL 备份。每次只使用一份来源，显示文件名、快照时间与覆盖情况。

首期支持结构版本 `23`，必要字段不兼容时明确失败。仅统计 Codex 会话导入明细及其日汇总，其他应用和代理记录不叠加。输入失败不得以旧结果冒充新来源。

成功读取后形成可复查的本地历史留存。用户可选择当前读取或一份历史留存进行分析，界面显示读取时间及实际覆盖；历史留存不表示实时状态，不自动跨多份来源相加。

### R2：日期筛选和期间预览

按北京时间选择起止日期，包含两端；默认当天，可选近 7 天、本月和自定义。首期统一按整日，不切分时分秒。

支持全部项目、指定项目和未归属筛选；项目与日期条件共同作用于预览及导出。项目筛选不得将同期其他项目、未知归属或未分配的历史日汇总自动塞入所选项目。

展示参考成本 USD、记录数、新增输入、输出、缓存读写及总 Token，提供每日、模型和逐条预览。历史日汇总保持真实粒度，区分其代表记录数与实际明细条数；没有记录的日期不据此宣称零消耗。固定导入状态码不当作官方 HTTP 成功证据。

### R3：证据包导出

一次下载 ZIP，包含逐条明细 CSV、每日汇总 CSV、可打印费用说明 HTML、导出信息 JSON。包名含项目、期间和导出标识，不覆盖既有版本。

首次可执行“创建批次并下载”；输出绑定批次及版本。相同版本再次下载复用原材料；改变内容产生新版本，旧材料保留。

CSV 使用 UTF-8 BOM，Excel 可正常读取中文、日期和金额；说明页使用简体中文，支持浏览器打印及用户手动另存 PDF。导出全部匹配数据，不限当前分页；有历史汇总时，明细小计加历史汇总小计等于期间总额，各日合计也相等。

### R4：来源、Token 与计价口径

预览和所有导出绑定同一快照、筛选条件和统计结果。记录来源指纹、结构版本、时区、覆盖粒度、计价说明及文件校验和，便于复查。

项目目录规则或人工归属变化后，原分析失效并重新计算。导出冻结项目名称、归属来源及规则版本，后续改名或改目录不重写既有证据包。

旧、新明细及日汇总按 CCS 相应输入语义归一，不重复计缓存。沿用来源保存金额，不按现价静默重算。价格依据缺失及未定价零金额可辨识，不将估算成本标成官方逐次扣款。

### R5：项目对象、目录绑定与归属修正

用户创建具有稳定身份的项目，填写名称和说明；一个项目可以绑定多个目录，目录可从已发现的会话目录中勾选，也可手动填写，因此 Windows 界面也能绑定日志中的 Linux 路径。

目录规则默认包含其子目录；同一规范化目录只能绑定一个项目。不同项目规则存在父子目录时，使用最长路径段匹配，确保一条记录至多属于一个项目。不同平台或同名目录只有经用户显式绑定后才视为同一项目。

已有可关联目录的历史明细和后续新明细均适用当前规则。命中已配置规则即自动归属，允许按记录或会话批量人工纠正；人工指定优先于目录规则，未命中、冲突或元数据缺失保持未归属。用户可以修改目录规则并重新归类，不改原始用量和成本。

旧日汇总没有会话 ID，不自动推断项目；用户可将选中的完整日汇总记录人工指定给项目，首期不在多个项目间按比例拆分单条历史汇总。

### R6：人工申请报销金额

保留期间参考成本；另设可选申请金额、币种（CNY / USD）和说明。填写金额须为非负有效金额、最多两位小数，并填写依据。空金额保持未填写，零金额保持零，不自动代填参考成本，不分摊订阅、不自动换算汇率。

### R7：原件、隐私与生命周期

数据在本机处理，不改变 CCS / Codex 配置、原数据库或日志，不上传用量或主动调用外部 AI。分享包不包含 API Key、账号配置、MCP、完整对话、IP、绝对原始路径或全库 SQL；用户原件留在原位置，不复制进 Git。

程序提供退出入口，退出释放端口并清理临时对象和内存；不后台常驻、不自启动。下载由用户选择保存位置，不自动写入现有 OneDrive 费用目录。

项目、目录绑定、人工归属、历史留存、报销批次和已生成材料保存在本工具自己的本地数据中，重启后保留；这类写入不涉及 CCS / Codex 原始数据库。首期不自动删除历史资料。

### R8：会话目录元数据关联

默认只读查找本机 Codex 会话目录，也可手动指定元数据根目录。通过 CCS `session_id` 关联普通或 Zstandard 压缩日志头中的工作目录，索引仅辅助定位；不分析聊天正文，不重新采集 Token 或重算成本。

无可用日志、日志冲突或仅有独立 SQL 备份时，明确显示识别覆盖与未归属情况，仍允许原有日期筛选和人工归属流程。找到目录不等于证明实际业务归属；归属依据来自用户配置的目录规则或人工指定。

### R9：必要明细与目录依据留存

每次成功读取时保存当时可用的 Codex 明细、历史汇总、必要计价信息及目录依据，来源清理明细或移走原文件后仍可独立打开已保存版本。仅保留业务投影，不保存全库配置或对话。

相同内容可复用存储对象，重复读取不增加用量或费用；来源修订保存为新版本，不覆盖旧版本。每次分析只选择一份留存，不自动把旧明细和新日汇总合并或相减，因此不会因多读几次而重复统计。

留存仅覆盖实际读到的数据；工具未打开时不保证捕获。原来仅有日汇总的部分仍按日汇总处理，首期不自动跨快照拼齐逐次数据。

### R10：报销批次、版本与重叠提醒

保存批次编号、所选数据/项目/期间、记录集合、用途、参考成本、申请金额/币种/说明及证据包。批次内容修改形成新版本，原版本、文件及其状态仍可复查。

各版本状态为草稿、已提交、已报销。初始草稿，后续由用户手动更新和纠正；生成或下载文件不自动表示已提交或已到账，新版本不继承旧版本的已报销状态。

重下载同一版本不新增批次，原包字节和校验和保持相同。重复点击或网络重试不生成多笔申请。

同一记录已出现在其他批次时提醒，区分草稿与已提交/已报销；历史汇总或明细/汇总跨粒度只能核对范围时，明确提示可能重叠。仅日期相同不等于重复报销。允许查看、重导已有批次或继续，不强制阻断，不自动扣减费用。

# CCS 更新后同步兼容修复

## 目标

恢复 CCS 更新后的 aha 用量同步，保留已有本地历史、项目归属和冻结材料，并交付与最终源码一致、可直接使用的 Windows 桌面单文件 EXE。

## 背景与已确认事实

- 用户报告 CCS 更新后 aha 无法同步；截图显示“仅支持 CC Switch 结构版本 23。”，已有本地明细 19,598 条、来源日汇总 110 条，上次成功为 2026-10-29 15:02。
- 当前基线为 main / f98df67，创建任务前工作区干净。
- `src/aha/sources.py:37` 在读取用量前要求 `PRAGMA user_version == 23`；仍会检查三个允许用量表的必要字段。
- Windows 原生只读探测确认已安装 CCS 4.0.24、当前源库结构版本 24；2026-10-30 的两份备份为 23，2026-11-02 备份为 24。三个允许用量表的列、类型、约束、默认值及主键在两版相同；上游 23→24 迁移只涉及其他应用开关和导入游标字段。依据见 [研究记录](research/compatibility-findings.md)。
- 实际 aha 应用库仍为 schema3，保留 19,598 条明细、115 条来源日汇总、4 个项目，报销和修订均为 0；截图与只读探测是不同时间点。最后一次同步失败为 `unsupported_schema`，当前源码基线在原生 Windows 上复现相同错误。
- SQLite、SQL 备份和内部历史投影共用或写死版本 23，`src/aha/evidence.py:428` 还将来源结构版本固定写入导出信息。外部源结构和内部格式需要分别核对。
- 用户先同意创建任务并规划，随后对最终方案回复“可以，继续吧”，已批准按方案实施并交付桌面单文件 EXE。

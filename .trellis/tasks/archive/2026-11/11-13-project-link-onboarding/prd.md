# 简化项目目录绑定与历史记录关联

状态：用户于2026-11-13批准最终规划，实施中。

## 目标

一个人工建立的 aha 项目汇集一组实际工作目录／Codex 项目。用户只选择纳入哪些目录；确认影响后，这些目录内有明确依据的已有记录整体归入该项目，后续记录同步时自动归入。换机时追加新目录，原项目身份、历史费用和已保存材料保持连续。

## 背景与依据

- 用户已授权创建任务并进入规划，已于2026-11-13回复“开始实施”，批准本版最终规划。
- 当前保存项目仅写目录配置，已有记录需到另一处筛选、全选、预览和确认；操作与用户按目录整体使用的心智模型不符。代码锚点与原生只读快照见 [研究依据](research/findings.md)。
- 用户已明确目录中的记录整体全用或不选，不逐条挑拣；又明确“目录绑到哪个项目，里面的记录就都归哪个项目”，包括以前人工分到其他项目的记录，确认前提示影响即可。
- 以上新决定覆盖旧合同在已确认目录范围内的人工例外／会话默认优先政策；未被本次确认纳管的旧目录与无目录记录不能在升级时静默重算。

## 需求与验收标准

| 编号 | 需求 | 可观察验收结果 |
| --- | --- | --- |
| R1 / A1 | 新建、编辑项目使用目录级整体选择 | 填项目名并选择／补充多个目录后，直接预览保存影响；无记录复选框、跨页全选、整会话开关或单独历史纳入开关。无目录也可保存空项目，不猜测记录。 |
| R2 / A2 | 一次确认保存绑定并整体归入历史 | 展示每个目录及原项目→目标项目的明细数、精确费用和总变化；确认后项目配置、目录归属、历史记录及统计一起生效；取消、过期或失败不部分绑定／部分迁入。零条历史仍可确认绑定，后续自动生效。 |
| R3 / A3 | 目录归属统一优先 | 本次确认目录中旧人工逐条例外、旧持久关系和相反会话默认不能留下拆分，也不能在重启、同步、费用修订或旧接口调用后恢复；不通过自动拆分会话获得目录范围外成员。 |
| R4 / A4 | 后续自动关联且处理迟到依据 | 新会话、旧会话新增用量、以后首次导入的历史用量，以及先入库后识别目录的记录，按已确认目录自动归入；无明确依据时保留待识别。自动关联随启动／手动同步及目录识别刷新发生，不增加定时采集。 |
| R5 / A5 | 目录整体转移与互斥 | 同一规范目录只归一个项目；从已有项目转入时，在同一预览中列明旧项目，确认后同时移动目录绑定和全部有依据记录。不同项目间父子目录重叠明确阻断并要求调整目录范围，不靠最长规则偷偷拆分用户选择的整体目录；同项目重叠去重。 |
| R6 / A6 | 换机与目录停用连续 | 新机路径追加到同一项目 UUID；旧日志缺失不撤销历史。移除且未转移的目录停止识别后续用量，已确认历史保留；转移给另一项目时按 A2 整体迁入。Windows／Linux 路径不凭相似字符串合并。 |
| R7 / A7 | 渐进接续已有项目 | 升级／启动不批量改旧项目历史；在项目卡显示确认目录关联入口，用户在同一流程审阅已有全部目录的影响并确认采用新模型；改名不改变项目 UUID。后续重复同配置保存不制造重复项目或归属事件。 |
| R8 / A8 | 明确无依据与冲突边界 | 无会话日汇总、缺目录或依据冲突的记录不按日期／名称猜入。展示可确定记录的完整范围及未纳入原因；唯一有效留存目录可在同次明确确认中复用历史恢复，冲突证据不得自动采用。 |
| R9 / A9 | 常用界面不再产生逐条例外 | 目录已确认的项目通过管理目录调整归属；原批量归属／会话按钮退出常用主流程。旧写接口对已纳管目录不得制造拆分，返回明确的目录级处理提示；无目录旧资料的必要处理入口收纳在高级区域。 |
| R10 / A10 | 费用与证据守恒 | 所有项目＋未归属的同口径金额、Token 与记录量精确守恒。原消费／版本、别名身份、报销占用、覆盖决定和旧 ZIP 字节不变；已报销／待核对的记录数量与费用分别说明。 |
| R11 / A11 | 异常与重试可恢复 | 编辑、关闭、迟到成功／409／断连不能套错项目；提交响应丢失可幂等重放，已成功但刷新失败只重查结果。同步／配置／占用变更使旧预览失效，不能部分应用。 |
| R12 / A12 | 可用成品与交付 | 完成对应源码／HTTP／浏览器检查、原生 Directory 和 OneFile 验收，交付最终源码一致的实际桌面单文件 EXE并核对 SHA；提供中文 What’s New、清理自有临时物及收尾发版评估。 |

## 范围外

- 不增加后台定时采集、开机自启或跨设备双向业务库合并；不自动上传资料或公开发布。
- 不自动把现有每个项目转换到新模型，不凭本轮旧快照写回真实资料。
- 不从聊天正文推断目录，不虚构日汇总的会话／明细，不按比例拆分费用。
- 不增加可在目录内逐条排除／保留相反项目的选项，不引入无界全库加载或超大目录异步作业系统。
- 本轮不提供跨项目父子重叠目录的自动切割；超出单次有界处理能力时明确阻断，不只处理前若干条。

## 已确认决定

- D1：一个 aha 项目对应一组实际目录，用户只在目录层选择全用或不用。
- D2：已有人工跨项目归属也随明确确认统一迁入，确认前提示原项目、范围和费用影响。
- D3：换机追加目录，沿用稳定项目身份；历史／占用／冻结原包继续保留。
- D4：最终规划已获批准，产品与本机交付已完成；设计与执行清单分别见 [设计](design.md)、[执行计划](implement.md)。

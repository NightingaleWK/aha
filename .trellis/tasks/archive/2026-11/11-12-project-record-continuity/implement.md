## 2. 执行顺序与模块职责

1. **升级与回退基础**：保留权威 schema3 DDL，新增应用 schema4 的记录关系/会话默认/归属事件；实现 schema3 无损升级及旧完整备份独立恢复，验证迁移前后事实、当前归属、统计、占用与原包不变。更新所有真实 ledger schema 消费者，产品版本仍走发布 PR。
2. **稳定归属核心**：新增关系领域入口，经 Store 事务门面调用；同步/重分类优先读取持久关系，复用共享优先级解析。保留内容指纹人工例外、已确认别名、来源核对合同。新会话默认可由已配置目录识别；整个会话分配覆盖未来新增记录。
3. **历史修复与待归属**：在下述恢复算法上实现预览/原子提交；支持筛选结果的有界全量选择、按目录/会话/时间批量分配与逐条例外。未匹配或多候选保持可操作的待办，不按项目名猜测，不反复要求找旧日志。
4. **规则调整与费用证据**：保存目录不回算已确认历史，追溯操作独立预览；统一项目摘要、明细、日/月统计、待归属进度及新材料覆盖说明，验证项目和未归属的精确总量守恒。新冻结说明与当次分析一起保存，旧包不回写。
5. **质量、真实恢复与桌面交付**：完成合成/真实副本/浏览器回归；构建并验证 Directory/OneFile；按最终审阅范围保全并恢复真实台账、交付桌面文件、核对基线，最后清理任务临时环境并准备发版评估。

易受影响的主文件为 migrations/backup、projects/ledger/sync、queries/batches/evidence、server 和 web/app.js/index.html/style.css。新增领域逻辑以职责拆分，不继续将恢复/审核/批量选择堆入页面或 Store 构造函数。

## 3. 历史依据恢复细节

1. 通过项目/会话/元数据版本模块增加受限只读候选选择和统计，使用既有规范路径与最长匹配；禁止猜测或简单选择最新版本。
2. 增加绑定修订号与元数据指纹的恢复预览/幂等原子提交；复用核对采用逻辑、事务和 ledger 统计刷新。范围只限选中的会话及关联 scopes。
3. 项目管理提供分原因分组、按目录/会话恢复和人工归属；动态 select、异步成功/失败/关闭/重试遵守现有状态合同。
4. 合成夹具覆盖缺旧日志、匹配原项目、未匹配、多个历史候选、明确否决、记录 override、目录冲突、并发同步/规则变化、失败回滚与响应丢失幂等。
5. 验收当前真实资料的一致副本：以当次预览重算基线，不将 37,165 永久硬编码成产品测试期望。以本轮基线可预测恢复 347 个目录、其中 297 会话/37,165 明细匹配已有项目，50 会话/1,813 明细仍未归属；另有新机 1,625 条无规则明细，不混为恢复失败。

## 4. 逐笔关系与会话默认细节

1. 持久逐笔关系是主要依据；会话默认和目录规则是识别与批量分配辅助。元数据缺失不删除已接受关系，规则修改不隐式重写历史。
2. 新增表走正式应用 schema 升级、无损迁移、旧完整备份恢复和失败回退；旧版拒绝新结构。严禁原地试用资料重建。
3. 统一 projects.classify 与 ledger.reclassify 对有效 override/持久记录关系/会话默认/目录规则的优先级，避免两套实现漂移。显式历史调整更新权威关系与审计，再刷新投影；不能直接只改 usage_records.project_id。
4. “整个会话”支持未来新增记录；保留旧逐条 overrides 的内容指纹语义，不推断旧操作意图。项目迁移保留 UUID，规则增加/停用展示影响。
5. 将绑定/依据/审核事件纳入备份，旧 schema3 备份严格校验后在新恢复目录迁移；原包/旧备份 SHA 不变。

## 5. 必需验证矩阵

| 场景 | 业务断言 |
| --- | --- |
| 新机没有任何旧日志 | 历史项目与已接受目录/归属保持；无来源也可查询 |
| 旧版本已将目录写为 missing | 唯一历史证据可预览恢复，金额/Token/消费 key 不改 |
| 多个有效历史目录/明确否决 | 不自动覆盖，核对可处理且无永久 stale 事项 |
| 有目录但未绑项目 | 保留未归属、可按目录/会话批量指定，不根据项目名猜测 |
| 按整个会话分配后补同步 | 新记录继承持续绑定；有效记录例外优先 |
| 改规则/移除旧目录/目录复用 | 默认历史归属与费用不变；显式追溯先预览后原子应用 |
| 批量选择筛选结果 | 超过当前页的符合条件记录均处理；明确范围/排除项/上限，无只改可见页的假成功 |
| 同一会话涉及不同项目 | 逐条关系/人工例外可维护；会话批量辅助不抹去例外或强迫混算 |
| 同一消费别名合并 | 仍只有一个消费和一个生效项目；不同项目候选需核对，不能双计 |
| 项目汇总与待归属进度 | 同口径项目之和加未归属等于总量，金额/Token 精确；明细与日/月/材料成员一致 |
| 已确认项目且同期有未归属 | 已确认成员仍可正常报销；未归属不混入项目，材料不冒称全部消费已归属 |
| 同步/人工归属/占用与预览并发 | 原子事务重检；过期预览拒绝，不能半应用 |
| 多次应用/断连重试/空间失败 | 幂等、全部回滚或可确认已提交，无重复事实或半恢复 |
| 仅有日汇总 | 保留完整粒度、原 suppressed 与覆盖核对；不能拆分或重复计入 |
| 已报销/已冻结材料 | claims、主体成员与各版本原包 SHA 保持；当前分析需重查 |
| schema3/新 schema 完整恢复 | 旧备份先按旧结构校验，新目录迁移成功，失败原库与原包仍可用 |
| 动态项目/键盘/迟到请求 | 当前选择、焦点和保存身份正确；过时错误不清新结果 |

实施时补充有意义的业务测试至 test_projects/test_device_continuity/test_backup/test_migrations/test_http 与 web_state，复用 test helpers；不把实现字符串对照当行为测试。

## 6. 检查与交付计划

本节保留实施前的检查方法，实际完成范围与通过记录见 [verification.md](verification.md) 及其引用报告。

按质量规范使用原生 Windows 隔离环境与修复版 SQLite：相关 unittest → 全量适用测试、Ruff、strict mypy、compileall → Node 状态回归和 JS 语法 → 真实浏览器 → 当前真实资料一致副本回归。具体命令在实施前以质量规范/现有脚本为准，避免在未满足 SQLite 门禁的 Linux系统解释器上冒充通过。

在已选任务环境下执行：

```text
python -m unittest discover -s tests -v
python -m ruff check src tests scripts
python -m mypy src/aha --cache-dir <本任务平台独立缓存>
python -m compileall -q src/aha
node --check src/aha/web/app.js
node --test tests/web_state.test.cjs
```

上述 python 必须明确映射本任务原生 Windows 环境；由 runner 保留真实返回码。先做变更对应测试再做完整检查，遇到失败修复后重跑相关范围，不制造重复大样本。浏览器至少覆盖历史恢复、跨页批量、逐条纠正、持续会话、项目统计/材料、键盘焦点及迟到成功/失败。

Windows功能实施默认沿用 scripts/build_windows.py：Directory 实际验收后构建 OneFile；通过 KnownFolder 查实际桌面，交付与最终源码一致的 aha.exe，复核 SHA、从桌面启动及退出。项目/材料链路变化按发布合同补相应 Excel/打印等专项，真实点击未执行就不记通过。

最终审阅范围明确包含本任务有充分依据的真实资料修复：新的完整备份 → 副本升级/恢复预览/提交通过 → 原库按当次数据重新预览核对 → 原子应用 → 对照消费/占用/原包/项目统计。审阅通过后复用这份授权，不再就相同的恢复和桌面交付重复询问；实际范围变化或出现无法判定的归属才另行处理。无依据项保留待办，不自动全部指派。

规划阶段仅产生小型文档和只读证据。用户批准实施后，已建立任务自有原生环境和隔离验证副本，构建并验收最终 EXE；完成真实台账修复及桌面交付。任务临时资源在最终桌面验收后按 [交付规范](../../spec/backend/delivery-and-cleanup.md) 清理，持久备份、真实原库和最终成品保留。

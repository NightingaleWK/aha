# aha 双端 Codex 用量采集

## 目标

aha 在 Windows 启动，从 Windows 本机和用户实际使用的 WSL 环境读取 Codex 原生会话。用量长期写入 aha 本地数据库，继续支持现有的项目归属、按时间与模型统计、参考费用、报销材料以及备份还原。用户使用新品时无需安装或启动 CC Switch。

## 背景

- 用户于 2026-11-24 同意立项并明确要求彻底移除 CCS 读取逻辑，保留 aha 的业务功能，先完成完整设计和执行计划。
- 用户已在两端跑过会话。本机只读核对发现两端分别写入了项目目录、模型和非零 Token 记录，且已从 Windows 通过 `wsl.exe` 实际读到 WSL 文件。
- 原有 aha 已有自有台账。默认资料目录中有 schema 4 台账、已入账明细和历史日汇总。现有完整备份装的是 aha 数据库、资料对象与全部报销原包。详见[规划依据](research/baseline.md)。

## 范围与要求

| 编号 | 要求 |
| --- | --- |
| R1 | Windows 与 WSL 两处 Codex 数据目录可确认并持续读取。启动和手动同步更新已有台账，分别显示两端读入结果、覆盖范围和最后成功时间。 |
| R2 | 从会话记录提取事件时间、会话与目录依据、模型、Token 和可验证的参考成本。持久化使用最小统计投影与核对所需证据。对话正文、提示、工具结果和凭据留在原始资料。 |
| R3 | 两端可分别提交和重试。会话跨端复制、回读、续接、分叉、压缩或归档时，已确认的同一用量只记一次。证据不足的候选可核对，合计与可报销成员只使用已确认事实。 |
| R4 | 已入账的 CCS 用量、旧日汇总、已保存金额、项目与归属、报销占用和全部冻结材料随 aha 台账保留。旧日汇总继续按整日使用。选择历史补采时先核对覆盖与成员，记录用户确认的冲突处理。 |
| R5 | 继续支持现有统计、项目目录关联、时间范围、报销与原包下载。新材料注明原生记录及价格依据。已保存的历史金额、冻结成员和旧原包字节保留原样。 |
| R6 | 保留 aha 的完整备份、HTTP 与离线 CLI 还原，并支持已有 schema 3 和 4 完整备份。还原到新资料目录，历史即时可查，本机 Codex 来源可重新关联。原始会话归档仍由 Codex 管理。 |
| R7 | 删除运行时和现行交付链中的 CCS 活库扫描、SQL 导入、默认路径、旧绑定与相应入口。历史记录可显示原始来源。外部 CCS 文件由用户自行保管。 |
| R8 | 通过 Windows Directory、OneFile 和实际桌面副本的独立验收。交付与最终源码一致的单文件 `aha.exe`，提供中文 What’s New 和验收回执。 |

## 数据处理决定

- 以已经入账的 aha 自有数据库和 aha 完整备份为历史基准。旧记录留在原台账体系内，按已确认的身份和金额查询。缺失部分通过尚可读取的 Codex 原生日志按范围补采。
- 只有外部 CCS 库或 SQL 里有、且找不到原生明细的内容，仍属于那份外部原件。若需要该段历史，可在升级前用现有旧版把经确认范围留存到 aha 台账，再通过完整备份接续。新版的输入是 aha 资料和 Codex 会话。
- 首次连接以当前 Windows Codex 根和一个已确认的 WSL 发行版及数据根为验收范围。目录选择和工作路径归属沿用明确的本机依据。
- 本次继续提供已有项目用量和参考费用。官方订阅剩余额度、购买或重置额度以及对话正文分析属于独立功能，本轮以现有功能为边界。

## 验收标准

| 验收项 | 可观察结果 |
| --- | --- |
| AC1 | 从 Windows 成品读到两端真实新会话的可核对 Token 和目录。项目、时间、模型筛选和统计一致。回读同样文件新增 0 笔。 |
| AC2 | WSL 不可用时 Windows 可以成功入账，原台账仍可查询。WSL 恢复后从已保存进度接续，无重复和静默跳读。 |
| AC3 | 同一会话从两端出现、恢复旧分卷或与旧历史重叠时，确定的同一消费在合计和占用中只出现一次。待核对项可见，旧冻结原包原字节下载。 |
| AC4 | 在无 CCS 的环境还原 v3、v4 和本版完整备份到独立目录。逐笔与日汇总、项目归属、占用、报销元数据、旧原包哈希与基准相符，本机源经选择后可继续同步。 |
| AC5 | CCS 路径、SQL 旧入口和生产依赖已移除。缺少 CCS 或旧配置仍留在机器上的情况下，启动、同步、项目、查询、备份与还原均按原生方案运行。 |
| AC6 | 新材料参考成本和来源说明可复查，原生与旧历史混合分析时遵守同一北京时间、成员选择和冻结范围。缺价或覆盖不足有明确提示。 |
| AC7 | Windows 成品验收通过，桌面文件与已验收单文件 SHA256 一致。已验证重开、退出、材料和备份流程，报告注明实际覆盖及回退方式。 |

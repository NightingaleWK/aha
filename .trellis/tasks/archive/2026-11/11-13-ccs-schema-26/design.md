# 设计：CCS 结构版本 26 兼容

## 行为差距与最小所有者

本机 CCS 的 26 具备全部必要用量字段，但 domain 的外部白名单在进入字段读取前拒绝它，启动只能显示已存历史。官方证据已确认投影兼容；最小产品修改为 `SUPPORTED_CCS_SCHEMA_VERSIONS` 增加 26，继续通过同一验证器服务 SQLite 与 SQL。

## 数据流与不变量

1. SQLite 在同一只读事务核实外部版本/必要字段并扫描白名单；SQL 只解释字面量、要求全部版本声明一致，不执行输入。
2. `source_schema_version=26` 经 sync_runs、HTTP job 和 ledger 传递；投影仍用版本23。
3. 消费 key、规范化内容 hash 和投影 hash 不含外部版本。相同投影仅升级版本不会制造新事实、修订、归属或占用。
4. 未知27、坏字段或混合版本继续走现有失败/清理路径，事实和最近成功时间不变；版本适配不绕过 needs_review、来源绑定或修订核对。
5. 应用 schema4、manifest4 与旧材料字段作用域不变，原包不回填、不重建。

## 文件边界

| 文件 | 必要原因 |

| `src/aha/domain.py` | 外部版本集合与提示的唯一所有者 |

| `README.md`、CCS兼容规范、后端主契约/index | 支持范围、固定依据及验收规范与最终实现同步 |

优先复用现有扫描、发布、版本元数据及测试夹具，不新增格式适配层。若实施发现必须改动 sources/sql_dump/sync 等生产模块，应先解释证据及对既有合同的影响并更新方案；不借兼容修复重构。

- 不修改页面交互、时间统计算法、材料结构或业务资料；不在本次授权中对外发布。

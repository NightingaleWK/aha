# 双端原生 Codex 用量采集执行计划

1. **固定投影与样本。** 在隔离资料目录确认两端实际是哪个 Codex 进程和数据根。对用户已跑的会话只读核对事件、完成状态与项目依据，保留脱敏的期望测试行。补普通/压缩、父分支、分页、重复快照和写入中尾行样本，建立逐笔对账表。
2. **验证读取路径。** 先做可取消的 Windows 与 WSL 文件枚举和分段读取。验证 Windows 调用既有 `wsl.exe` 后的原生读量、耗时、退出和不可达行为，避免经 UNC 高频反复扫整库。给出后续增量操作的文件数、实际读量和耗时基线。
3. **落实解析。** 重用会话元数据有界读取与路径逻辑，为已验证形态提取事件、模型、Token、缓存和会话/分卷关系。对累计基线变化、成对事件、缺价、损坏段和部分尾行提供测试场景。逐笔确认期望金额所用的参考价格及版本。
4. **接入暂存和事务。** 实现原生事件身份、来源证据、进度和 schema 5 的新增结构，在隔离台账先验证。复用现有台账发布与查询，确保一次事务中事件、业务关联和进度一致。用相同输入两遍、跨源复制、回档、换目录、复用长会话和不同来源一端失败完成验证。历史子任务负责启用旧版到目标结构的实际升级路径。
5. **接入来源状态。** 在隔离运行的启动、手动同步和状态接口中展示两个来源的读入及最后成功情况，验证取消、迟到响应、清楚的覆盖状态和键盘/焦点。项目选定、时间范围、报销入口与原交互一致。正式退役旧入口在历史子任务做。
6. **检查和交接。** 运行来源、台账、项目、HTTP、浏览器和同批回读用例，记录真实 Windows/WSL 与合成测试证据。在用户资料副本中只读核对相同样本的投影。将 schema 5 增量结构、事件键、游标和来源状态的依据交给历史子任务。

## 回退与进度

本子任务初始使用只含测试事实的独立目录，原生取数仍可在生产切换前取消。失败时检查并保存已提交源的回执，未提交数据可重放。出现未知文件形态时先复现和记录覆盖原因，再扩展解析，最后重跑同批去重检查。

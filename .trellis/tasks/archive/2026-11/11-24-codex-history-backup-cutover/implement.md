# 历史台账迁移与备份还原执行计划

1. **建立基准。** 在隔离资料中准备 v3、v4 的有效完整备份和失败样本，包含历史日汇总、项目、已占用明细、多版本材料和待核对历史。保存业务计数、历史成本、项目成员、占用、修订、材料指纹及旧 DDL。对正在使用的资料只读取升级方案所需的指标。
2. **落实升级和还原。** 固定 v3/v4 的真实定义，接入原生子任务交付的 schema 5 增量结构。使当前资料升级与恢复分段验证，保留旧身份及数据。共用全量备份严格校验，保留无覆盖、分块/取消、离线 CLI 和应用内恢复。确定恢复后本机来源重绑和偏移重建行为。
3. **完成历史核对。** 在现有台账发布入口接入原生证据与既有核对。预演重复、真实缺失、多个候选、日汇总和被占用记录，覆盖预览失效及重试。证明无假新增、无现价覆盖、无冻结包重建，旧数据查阅始终可用。
4. **切换生产入口并退出 CCS。** 替换启动、手动、状态与绑定。移除 SQLite/SQL 导入及活库读取实现、相关错误码或命令、默认位置、页面控件和大请求分支。同步迁移帮助及现行规范、测试样本和成品验证脚本。历史来源文字留作已存证据。
5. **跑备份专项。** 用 schema 3/4 历史备份到独立目录，新版生成完整包后往返，校验原包哈希和归属/占用。覆盖覆写目标、结构篡改、差错哈希、空间失败、取消、崩溃中断、路径变动和同机/换机恢复后再次增量。
6. **跑业务与退役专项。** 真实 HTTP/浏览器核对切换、历史过滤、项目关联、保存与 ZIP 下载。验证 Windows 与 WSL 新明细混合旧事实，时间和金额口径贯通。隔离环境移除 CCS 可达路径，检查原生启动、同步、备份、还原路径。报告列出已清理入口与仍保存的历史证据。
7. **交接。** 保存失败/回退指纹与旧备份兼容结果，供主任务的 Directory、OneFile、桌面验收使用。生产资料处理使用已校验的旧版回退件及用户批准的切换范围。

## 关键检查入口

- `tests/test_backup.py`、`test_http_backup.py`、`test_backup_cli.py`、`test_migrations.py` 现有往返、安全和版本检查，增加 schema 4 到 5、重绑后重读和历史冻结保持的用例。
- `tests/test_evidence.py`、`test_time_ranges.py`、`test_assignment_migration.py`、`test_directory_bindings.py`、`test_claim_concurrency.py` 等现有业务检查，核对旧与原生混合范围。
- `scripts/verify_windows_artifact.py` 验证成品实际启动、浏览器、材料、完整备份和恢复。云端合成来源检查与本机实 WSL 证据分别记录。

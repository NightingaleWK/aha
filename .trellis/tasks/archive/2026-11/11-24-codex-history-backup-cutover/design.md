# 历史台账迁移、备份还原与 CCS 退出设计

## 资料的去向

| 资料 | 新版的处理 |
| --- | --- |
| 已存在于 aha 的历史用量 | 保持已发布记录键、内容版本、原始来源证据和历史金额。原生事件接续到同一本账，另记其可验证的来源。 |
| 独立于明细的历史日汇总 | 保持原有日粒度和覆盖依据。已确认整天可按原有规则查询，部分日或未知重叠沿用既有提示。 |
| 已存项目与报销 | 保持目录规则、人工关系、可用成员、占用、修订和冻结包。旧 ZIP 下载保持原字节。 |
| 原生日志中可恢复的未入账用量 | 在明确范围内预览补采，按事件证据、覆盖与已占用成员分类，然后接入当期或受控补录。 |
| 仅存在于外部 CCS 文件的历史 | 外部原件继续由用户保管。需要该段历史时，先由旧版按确认范围将可用事实留存至旧 aha，再生成并校验完整备份。新版还原以 aha 完整备份为输入。 |

## 重叠核对与正式切换

1. 从已确认的完整备份还原一份独立旧账本，并记录业务基准。预览只读读取台账自身的历史、价格、目录、已占用情况与新原生日志允许投影。切换方案以事实覆盖、风险和选择范围为依据。
2. 生成每一来源在指定范围的核对结果和与旧历史的对应关系。已确认事件和旧事实建立证据联系，继续使用既有身份与原金额。旧来源标识与原生标识受明确的映射验证，不能仅凭同日、模型、时间、Token 或等价金额认定相同。
3. 能确认为新事实时加入当前台账。有未确认重叠、同一候选字段冲突或缺少汇总成员时使用现有核对候选及原生证据。保留可查历史，待核对部分暂不进入可用合计，已有报销占用继续由既有成员身份保护。已确认重复保存映射，使机器重开、重读和还原后结果一致。
4. 发布切换时在同一事务重新核对预览的资料、发生版本和占用状态。若预览已失效重新生成。完整快照跨到新采集边界时保留已发布的确定基线；在切换线前补采时继续使用重叠核对。
5. 正式窗口使用先校验备份、再迁移台账、再确认原生来源的顺序。已有旧资料的首次启动展示来源接续状态，确认后恢复自动和手动采集。可视化核对项目/事件数、Token 和参考成本，发现不明重叠时保持原数据可用。

## 应用数据库与存档兼容

新增持久化表需要应用 schema 5。维持原有全量备份容器格式 `aha-full-backup` 及 `format_version=1`，用 `store_schema_version` 标记数据库版本。schema 3 和 4 保持各自真实的 DDL、索引与触发器定义，不在升级入口把旧版解释成最新版。

- 汇合 `migrations.py` 的结构定义和 `backup.py` 的严格校验。应用启动与独立恢复分别使用同一份版本化定义。保留 schema 3 到 4 的既有项目迁移及事实身份，再执行 4 到 5 的添加与接续标识迁移。每段使用明确目标版本，在事务内验证结构、引用和事实基准。
- 升级选取 additive 结构和本机来源状态。旧 `usage_versions`、`record_evidence`、`record_aliases`、日汇总证据、项目表、`usage_claims`、报销修订及 ZIP 登记继续读同样的数据。历史来源类型用于解释已有事实，去除能使旧设置触发实时读取的逻辑。
- 备份仍从一致 SQLite 快照复制已提交事实，并核验对象和原包哈希。新备份可包含持久化原生事件身份及证据。已保存统计、旧来源依据和归属随数据库搬迁。日志、登录、锁、运行凭据及临时工作区继续留在本机运行边界。
- 对旧完整包先按各自 schema 验清单、版本、精确 DDL、数据库完整性、外键、对象与包。验证后在独立恢复目录进行升级、处理未完成运行及写入恢复标记，最后按现有无覆盖发布。原 ZIP 和其中的所有报销原包保持原字节。
- 原生读取偏移绑定安装、来源实例和还原身份。即便在同机还原，也重新验证本机来源。失效来源偏移可清除或标为待重建，已发布事件证据用于跨目录、换机和压缩回读去重。历史项目目录仍可使用，不用新机器路径批量重设旧记录。
- `--backup` 和 `--restore-backup --restore-dir` 保持离线，不启动自动同步。HTTP 保留现有上传、还原、取消、打开独立资料与认证边界。清单、分块及恢复安全失败继续明确反馈。

## CCS 读取退役清单

| 层 | 接口与文件审查 |
| --- | --- |
| 外部入口 | 移除旧 SQLite 路径及 `/api/source/sqlite`、`/api/source/sql`，以及旧路径绑定与大体积 SQL 上传的分支。新 `/api/sync` 与状态以确认的 Codex 源为准。 |
| 读取与解析 | 移除 `sources.py` 的外部 SQLite 扫描、`sql_dump.py` 的 SQL 扫描、`sync.py` 的对应入口与淘汰的 CCS schema 门禁。保留台账可复用的投影、发布和事务。 |
| 本机绑定 | 从 `source_bindings.py` 抽出或复用实际需要的通用安装身份，替换只针对旧 CCS 文件的绑定和默认路径。运行时不使用历史来源的 `location` 打开文件。 |
| UI 与材料 | 删除 CCS 数据库/SQL 选择、旧绑定流程与提示。继续可看来源、备份与还原、核对和导出。新材料说明原生与历史价格依据，历史冻结包走现有原字节链。 |
| 测试和交付 | 将成品验证使用的假 CCS 活库换成合成原生日志。旧结构测试可使用已归一化的 aha 资料或独立旧备份夹具。检查试用重建、基准、README、活跃规范与构建工作流，退出仍可打开外部 CCS 文件的现行逻辑。 |

退役依据是产品源码、HTTP、CLI、程序启动和发布验证入口均以原生数据和 aha 台账为输入。历史记录、恢复夹具和既有档案可保留来源文字与结构证据。分别在无 CCS 的验证环境及本机隔离资料中检查启动、同步与备份还原，放置不可读的旧路径配置验证运行时的路径访问边界。

## 成品的回退路径

生产升级前通过已有完整备份路径保存可恢复快照，在新目录演练还原并记录原包 SHA256。迁移事务失败回滚旧库。需要回退时用旧 EXE 打开从升级前备份还原的独立资料目录，新版台账和新产生的报销材料另行保全。两份业务库的成员占用以选定账本为准，避免双边继续登记同一期报销。

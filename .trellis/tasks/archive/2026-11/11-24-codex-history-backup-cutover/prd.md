# 历史台账迁移与备份还原

## 目标

把现有 aha 台账与完整备份带入原生采集版本，并彻底退出 CCS 读取路径。承接主任务 R4、R5、R6、R7。 [主需求](../11-24-codex-dual-source-usage/prd.md)

## 要求

- 保全已入账用量、日汇总、参考金额、身份与版本、人工和目录归属、占用、报销关系和每个冻结原包。缺少当年日志时仍可查询历史和重下原包。
- 在已验证的旧备份及隔离副本上确定新增、重复和待核对部分。重叠证据足够才复用既有身份。未知覆盖的日汇总以及字段差异可核对。
- 继续兼容旧 aha schema 3、4 的完整备份与现有完整备份入口。新版还原到独立目录可立即查看记录，选择本机原生源后继续同步。
- 产品启动、手动同步、来源配置、HTTP、帮助及现行验证入口均使用 Codex 原生流程。退出 CCS 活库、SQL 及对应默认地址、源绑定和帮助文案。
- 使用旧工具移交到 aha 的已入账事实保留来源依据。若旧历史只在外部文件中，默认保存原件及范围说明，过渡不改动该文件。

## 验收

| 编号 | 结果 |
| --- | --- |
| M1 | 用隔离 schema 4 台账走升级，保全旧明细/日汇总、项目/关联、占用、修订和旧成本，逐版下载的 SHA256 一致。模拟中断或验证失败后可使用原台账或旧备份。 |
| M2 | 用真实结构的 schema 3、4 完整归档与新版完整包分别还原。哈希、结构、引用、还原边界通过校验，CLI 和 UI 可用。原备份及旧原包不改写。 |
| M3 | 还原时两端路径变化、缺历史日志或重新选择资料根的场景，已有历史、目录与占用可用。确认本机来源后的重复回读无新增同一消费。 |
| M4 | 现有项目统计、查询、编辑、冻结与重新下载都可使用。历史和新原生用量可在同一范围分析，重叠待核对有明确覆盖提示。 |
| M5 | 在 CCS 不可用或留有旧配置的隔离环境，启动和手动同步、备份还原、测试工具及成品入口均完成原生流程。旧 SQLite 和 SQL 导入入口已移除。 |

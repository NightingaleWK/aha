# 完整备份与还原设计

总体边界见[父设计](../11-12-device-data-continuity/design.md)。新增职责明确的备份模块，通过Store门面/CLI/认证HTTP复用，不复制第二套金额或占用计算。

备份：SQLite backup API产生独立一致快照 → 读取快照全部revisions引用 → 原包存在性/哈希核验 → 分块归档与manifest → 原子发布备份成品。慢文件生成不长期占writer锁；已提交WAL纳入，未来新材料不污染快照。未知持久对象显式识别/保留，不借备份流程清理真实文件。

还原：限额流式接收 → 独占新staging → 验证路径/成员/manifest/文件SHA → 只读DB完整性/schema/外键/材料引用检查 → 完整目录原子落位。目标必须新目录，不替换活动库、不混搭DB/包；失败保留原库并清理确认归属的staging。恢复包中的机器绑定不当成本机来源授权。

页面区分“导入CCS用量备份”与“完整aha备份/还原”，包含下载、上传、结果目录/打开说明、错误及取消恢复。大包传输不走SQL的128MiB JSON/base64入口，使用独立有界分块路径。CLI支持离线恢复到指定新目录，具体参数在实现时保持测试与帮助一致。

清单格式独立于应用schema/外部CCS/内部projection。旧schema3当前备份可恢复，不自动重建旧schema1/2；旧冻结ZIP不重算。备份为私有资料，不复用费用分享过滤协议丢失恢复所需信息，也不附CCS账号配置。

# 移除旧日汇总并修复同步误报

## 目标

aha 的用量、项目统计和新报销以可追溯的逐笔明细为基础。移除 CC Switch 留下的历史日汇总及其活动数据。修复本机 Windows 和 WSL 都遇到的上下文压缩误报。

## 已确认的事实与决定

- 用户在了解数据量、费用影响和备份方案后，要求移除程序中的旧历史日汇总及本机相应数据，随后明确选择建任务并实施。
- 本机 schema 5 台账只读核对发现 117 条旧汇总。其中 110 条计入历史参考费用，另 7 条被明细替代。117 条的项目、会话、目录和报销引用均为空。同期 310 条待归属逐笔明细另有真实记录。
- 同一组 Windows 归档和 WSL 普通日志内有三条超出 1 MiB 的上下文压缩事件。旧读取器丢弃事件并清空累计基准，随后误报上下文估算。从只读模拟取得的 662 条明细身份、Token 和参考费用逐条一致，六次提示消失。

## 要求

- **R1** 清空历史日汇总的活动记录、关联和派生数据。首次打开旧台账先生成完整可回退备份，迁移使用同一事务。升级和受支持的备份还原均进入只保留逐笔明细的当前模型。
- **R2** 退出历史日汇总的导入、统计、归属、明细入口和新材料成员选择。按日视图、趋势和材料《每日汇总》由逐笔明细计算。存量冻结材料可查看和重下原文件，已报销或占用范围保留作为防止重复申请的依据。
- **R3** 保留有界解析。可验证的超长上下文压缩事件延续已有压缩状态处理，未知或用量相关的超长记录继续报告覆盖风险。更新受影响文件的旧读取进度并按稳定的明细身份去重。
- **R4** 交付和验收与最终代码一致的 Windows 桌面单文件 EXE。先在隔离资料核对回退副本，再用用户当前台账执行已授权的清理，并实测两个来源的终态。

## 验收

- [x] **AC1（R1）** schema 5 迁移后活动历史汇总为零，逐笔事实、关联、费用和已有报销可用，日月统计一致。支持 schema 3、4、5 和当前版本备份还原，保留旧材料原 SHA。模拟迁移失败时原资料可打开或从完整备份回退。
- [x] **AC2（R2）** 工作台、待归属及新导出均使用逐笔明细。按日统计、分钟筛选、趋势、项目归属和生成新材料遵循同一成员选择。
- [x] **AC3（R3）** 普通和 Zstandard 归档的超长压缩事件、分块续读、真实未核实用量及旧游标补扫有回归覆盖。已知两端日志在修复后明细一致。
- [x] **AC4（R4）** 本机实际台账清理后旧汇总为零，完整回退备份核验通过。Windows 和 WSL 都完成同步时，页面显示「已同步」并更新成功时间。记录证据并交付经原生验收的桌面 EXE。

## 边界

数据范围为 aha 活动台账中的旧 CC Switch 历史日汇总。本机 Codex 源文件、CC Switch 原件、历史备份和旧报销原包作为各自的来源或回退依据。

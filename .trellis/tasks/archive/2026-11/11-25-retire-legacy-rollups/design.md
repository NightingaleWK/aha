# 设计

## 台账和迁移

当前 schema 增加一个版本。为旧 schema 保留验证定义，并通过现有 Store 升级入口在写事务前保全完整备份。备份还原复用同一迁移，目标写入隔离资料目录。

以旧活动记录的身份清理汇总事实、非冻结版本与证据、关联和派生统计，整合现存明细的覆盖和占用状态。存量冻结版本及原包仍从已保存记录读取，曾占用的范围仍参与防重。旧范围的冻结用量不进入任何新生成材料。新表写入口约束活动记录只接收明细。旧备份和外部历史投影在输入边界识别旧格式。

当前用量选择、汇总、归属、报销和 Web 使用同一逐笔成员。按日和按模型均为这些成员的聚合。新的界面和材料不再介绍来源日汇总、部分日省略或汇总待归属。兼容分支只服务原有冻结历史和旧格式迁移。

## 原生日志

使有界读取能够辨认超长上下文压缩事件的固定日志结构。即使一行跨越读取块或已保存的文件进度，也在行完成后应用现有压缩状态。未知记录保留覆盖警告，累计用量仍使用现有验证。旧游标只对已标记的文件补扫，扫描使用原生事件身份、发布事务和事实去重。

整批成功取决于两个已配置来源都到达成功或无新增终态。实际环境中新出现的覆盖错误继续按来源显示。

## 运营

先使用隔离资料验证迁移、旧材料和可恢复性，再迁移本机台账。保留一个可验证的升级前完整备份，记录数据库和成品校验，但报告只包含脱敏计数和状态。

# 项目识别可行性

研究日期：2026-10-27。由用户提问“项目识别这个，有可能识别吗？”触发，只读研究完成后，用户已确认首期纳入项目对象及多目录绑定；仍处于规划，未实现产品代码。

## 结论

能够将 CCS 逐条用量的 `session_id` 与本机 Codex 会话元数据关联，取得工作目录 `cwd`，再按用户维护的目录与项目映射提出项目建议。此方案不需要调用 AI，也不需要分析完整聊天内容。

“找到工作目录”是可验证的技术关联，不等于自动证明业务项目归属。用户先创建项目并手动确认所属目录；之后命中该已配置规则的记录自动归属，不要求逐条再确认，仍允许纠正并保留未归属。

- 10,852 条 Codex 明细涉及 178 个不同 `session_id`。
- Windows `%USERPROFILE%\.codex\state_5.sqlite` 的 `threads` 表含 `id`、`cwd`、`rollout_path` 等字段。仅查 ID、工作目录与日志路径，没有读取标题、提示词、首条消息、账号或凭据。
- 单凭当前 Windows 索引可关联 109 个会话、6,688 条明细；相关行 `project_id` 均为空，不能依赖该列识别业务项目。
- 部分索引中的日志路径现已失效或与实际归档位置不同，故索引不是历史完整性的唯一依据。
- 在 Windows Codex 的 `sessions` 和 `archived_sessions` 下按相关 UUID 定位了 179 个候选文件，其中 122 个为 `.jsonl.zst`。只读取有界文件头，提取 `session_meta.payload.id/cwd` 及可选父线程标识，不扫描对话正文。
- 178 个会话全部找到非空 `cwd`，覆盖备份全部 10,852 条明细；候选文件头解析错误为 0，多文件间同一会话出现不同头部 `cwd` 的情况为 0。

- 这是所给备份在当前机器、当前日志保留状态下的关联覆盖率，不能泛化为未来数据、其他机器或业务归属准确率。

## 上游依据

[CC Switch 会话元数据读取](https://github.com/farion1231/cc-switch/blob/e55d8a21b3897b595b746e9f2139716b2931641d/src-tauri/src/session_manager/providers/codex.rs#L1973)在 `session_meta` 中取得会话 ID，并将 `payload.cwd` 读取为 `project_dir`。其会话阅读能力已经能取得目录，但用量表没有直接保存项目名称。

[CC Switch 用量写入](https://github.com/farion1231/cc-switch/blob/e55d8a21b3897b595b746e9f2139716b2931641d/src-tauri/src/services/session_usage_codex.rs#L2208)保留会话线程标识，为目录元数据关联提供键。只补充元数据，不需要重新计算 Token、重导原始用量或替换 CCS 已保存金额。

## 建议的识别流程

1. 保持 CCS 为用量和参考成本来源。
2. 将会话 ID 关联到 Codex 头部元数据；当前索引可辅助定位，索引不足时读取活动及归档日志头，也支持压缩日志。
3. 规范化 Windows 路径前缀、分隔符和大小写规则；Linux 大小写保持原义。目录匹配按完整路径段及最长已配置前缀，不能仅比对同名末级目录。
4. 用户一次性配置目录或别名到项目名称的映射，例如将实际确认的目录映射为“流萤”“萤石”；同一项目的多个路径需显式归并。
5. 明细显示项目及目录规则/人工指定/未归属来源。命中已配置目录自动归属，用户按项目筛选导出；未知目录、冲突或元数据缺失进入待确认，不强行分配。
6. 归属规则和人工修正保存在本工具自己的数据中，不修改 CCS 或 Codex。导出只保留必要识别依据，不泄露完整本机路径或对话。

## 边界及首期影响

- 历史 `usage_daily_rollups` 没有会话 ID，不能通过这条关联链直接拆回项目；按原计划提供每日汇总及人工归属。若未来从原日志重建历史，须作为单独采集和对账范围评估。
- 通用目录、项目外问答、一个会话讨论多个项目、会话期间迁移目录或工作树，都可能使起始工作目录与实际业务归属不同。本次只核对头部元数据，未逐轮检查 `turn_context.cwd` 是否变化。
- 工作树与 Windows / WSL 路径别名不能凭名字强行合并；可用现存仓库元数据提出候选，但应允许人工映射。
- 单独拿走 SQL 备份、不提供相应 Codex 元数据时，无法保证识别，仍保留原有按日期人工归属流程。
- 用户已确认首期增加项目对象、本地元数据目录选择、多目录绑定、自动规则归属/人工修正、项目筛选和相应导出字段；用量采集与金额计算仍沿用原设计。
- PRD、设计、实施计划及验收已随该决定更新；当前没有实现产品代码或启动任务实施。
